# Декомпозиция личного проекта

Ты пишешь декомпозицию личного проекта: проверки и задачи, по которым
исполнитель (spec-runner) построит код. Основания — дизайн `20-design.md`
(решения D-NN) и бриф `00-brief.md` (функции FR-NN и их критерии приёмки).
Прочитай оба целиком перед тем, как писать.

Критерий брифа называется `FR-NN/k`, где k — номер критерия в списке
«Критерии приёмки» этой функции, с единицы: второй критерий FR-01 — `FR-01/2`.

## Разметка — строго, её читает машина

Файл без YAML-шапки, ровно два раздела второго уровня в этом порядке:
`## Проверки`, затем `## Задачи`. Внутри разделов — никаких заголовков
уровней 1–3 (`#`, `##`, `###`): они обрывают блок.

### Раздел `## Проверки`

Каждая проверка — блок:

```
#### BEH-01: <что проверяет, одной строкой>
<1–3 строки: наблюдаемое поведение — что сделать и что должно получиться>
- **checked_by**: `kind: pytest` `target: tests/test_notes.py::test_add_prints_total`
**Критерии:** FR-01/1, FR-01/2
```

- Заголовок — ровно `#### BEH-NN: <название>`: BEH-01, BEH-02, … по
  порядку, двузначный номер, двоеточие и название обязательны.
- `**checked_by**` — ровно одна строка на проверку, оба поля в обратных
  кавычках: `kind:` — `pytest` (автоматический тест) или `manual` (проверка
  руками, только если автоматически нельзя); `target:` — путь к тесту
  (`tests/<файл>.py::<тест>`) или, для `manual`, путь к документу с шагами.
- `**Критерии:**` — критерии брифа, которые эта проверка подтверждает, через
  запятую. **Каждый критерий каждой функции брифа покрыт хотя бы одной
  проверкой.** Ссылайся только на существующие критерии.

### Раздел `## Задачи`

Каждая задача — блок:

```
#### DT-01: <что делает задача> · type: implement · owner: dev
scenarios: [BEH-01]
depends_on: []
parallel_group: solo
**Решения дизайна:** D-01
<1–3 строки: что сделать, границы задачи>
```

- Заголовок — ровно `#### DT-NN: <название> · type: implement · owner: dev`
  (разделители — `·`); DT-01, DT-02, … по порядку.
- `scenarios: [BEH-01, BEH-02]` — проверки, которые задача делает зелёными.
  Каждая проверка принадлежит **ровно одной** задаче; у задачи — хотя бы
  одна проверка.
- Тестовый файл (`target` без `::…`) принадлежит одной задаче: проверки
  разных задач — в разных файлах.
- `depends_on: [DT-01]` — задачи, которые должны быть сделаны раньше; только
  объявленные **выше** по документу, без циклов; пусто — `depends_on: []`.
- `parallel_group: solo` — всегда `solo`.
- `**Решения дизайна:**` — решения D-NN дизайна, которые задача реализует;
  задача без решения дизайна — не задача этого проекта.
- Других служебных строк (`delivers:`, `verifies:`, `delivered_by:`,
  `tdd_waiver:`) не пиши.

Задачи — по существу проекта: обычно от одной до пяти, не дроби мелко.
Не вводи обязательств, которых нет в дизайне и брифе.
