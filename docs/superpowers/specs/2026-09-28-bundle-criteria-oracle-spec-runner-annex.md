# Приложение к заявке spec-runner: механизм измерения `criteria-closure/v1`

Дата: 2026-09-28. Статус: **предложение соседу**, не норма devtools (rev 6).
Основание — спека `2026-09-28-bundle-criteria-oracle-design.md` §4 (гарантии
G0–G6, род BEH, наблюдаемые поля). Владелец механизма — spec-runner: он вправе
реализовать гарантии иначе, если ответ несёт поля §4.3 и выполняет §4.1–4.2.
devtools проверяет только контракт.

Ниже — реализация, прототип которой прошёл замер 6 на честном воркстриме devtools
i5/#171 (скрипты прототипа — dev-скретч `v6.py`, `memplug.py`; в заявку
прикладываются описанием, не кодом).

## M0. Окружение

Свежий клон репо-владельца на `product_sha`; `uv sync --frozen` из клона (общий
кэш uv — намеренно). `PYTEST_ADDOPTS` и прочие `PYTEST_*` вызова очищаются;
конфигурация pytest репо — часть продукта. Импортируемый продукт — из продуктовых
корней клона (иначе `error: foreign-import`). Продуктовые корни — исходные файлы,
которым соответствуют файлы колеса на `product_sha` (через `RECORD` по sha256);
файл колеса без пары — `error: product-roots-unknown`.

## M1. Сбор, покрытие по фазе, подпроцессы

`pytest --collect-only` всего набора — авторитетное множество; селектор →
определение (файл + qualname) → токены по §1.4 спеки. Покрытие — coverage.py с
динамическими контекстами (`--cov-context=test`); в расчёт идут только строки
контекста `|run` в продуктовых корнях. Запуски дочерних процессов в фазе `call`
пишутся хуком на `subprocess.Popen`/`os.posix_spawn`/`os.exec*` (argv); селектор,
исполняющий продукт только в дочернем процессе, — `subprocess-only`.

## M2. «Обнаружил тест» (G2)

Хук `pytest_runtest_makereport` (фаза `call`): красный засчитывается, если тип
`AssertionError` или `Failed` (`pytest.fail`, «DID NOT RAISE») и файл кадра, где
исключение брошено, — собранный тестовый файл, `conftest.py`, модуль плагина
pytest (`config.pluginmanager`) или тестового хелпера. Номера строк в
`inspect`/трейсбеке при базе в памяти могут не совпадать с диском —
классификация использует только путь файла.

## M3. База изменения в памяти

1. Дифф каждого `change_commits` против первого родителя, продуктовые файлы.
2. Операторы (AST-statement), изменённые или добавленные диффом и исполненные
   селекторами BEH в `|run` на `product_sha`, заменяются в исходнике модуля на
   сторону первого родителя; докстринги и сигнатуры не операторы — не трогаются.
3. Изменённый исходник подаётся хуком импорта (`sys.meta_path`-finder,
   компиляция с исходным путём файла); **файл на диске остаётся HEAD**, поэтому
   `inspect.getsource`, хэши и чтение текста видят HEAD.
4. Не компилируется/не импортируется — `base-unbuildable`.
5. Прогон: каждый селектор дважды на HEAD (флейки-проверка), затем решающий
   красный — чередование база/HEAD K = 2 с единогласием.
