# selfcheck: самодиагностика devtools и флота — баги, мёртвое, дубли, заменимые LLM-вызовы

Дата: 2026-09-25. Статус: **draft, rev 2** — дизайн согласован с владельцем по
секциям в сессии 2026-09-25; rev 2 закрывает локальное Codex-ревью rev 1
(7 must-fix, 4 should-fix, 1 minor). Цикл — vault rule
`authored/rules/spec-authoring.md`; PR откроется один — на пару «спека + план».

Основания:
- запрос владельца: средство самодиагностики с упором на **предложения по
  упрощению** (неиспользуемые и дублированные скрипты/модули/цели), по максимуму
  на линтерах, скриптах и анализаторах; плюс проверка «можно ли LLM-вызов
  заменить скриптом, алгоритмом принятия решений или малой моделью»;
- ручной инвентарь LLM-вызовов 2026-09-02 (dev-only, `_cowork_output/`) —
  **только** эталон ручной приёмки S3; ни runtime, ни тесты его не читают;
- набор репо — `workspace-manifest.toml` зонтика (`$(MANIFEST)` в `Makefile`).

## 0. Цель и границы

`selfcheck` — детерминированный конвейер проб над репо, выдающий **отчёт**
(JSON + Markdown) с находками категорий: bug, quality, dead, duplicate, deps,
llm-replaceable, selfcheck (о самом приборе). Главная ценность — dead и
duplicate для скриптов devtools, целей `Makefile`, skills и slash-команд.

Критерии успеха:
1. каждая проба видна в сводной таблице прогона (версия, argv, код выхода,
   статус, покрытие входов, число находок); проба, чей анализ неполон или
   не подтверждён, — находка, а не тишина (§4);
2. каждый исполняемый узел devtools получает класс использования с рёбрами-
   доказательствами (§3.2); на известных трудных вызывающих (§6.1) ложных
   dead нет;
3. находки имеют стабильную идентичность (§2.1) и `owner_repo` — формат готов
   к автозаведению issues без переделки;
4. каждое правило на фикстуре срабатывает на своём случае и не срабатывает на
   отрицательном двойнике (§6);
5. прогон не пишет в сканируемые checkout'ы (§1.3); LLM без `--judge` не
   вызывается, с `--judge` — без инструментов и доступа к файлам (§5).

Вне объёма (S1–S5): автофиксы и автоудаление; автозаведение issues; CI-гейт
(решается после нескольких прогонов по доле ложных срабатываний); правка
соседних репо; runtime-телеметрия фактических запусков (§3.2, «корни»);
LLM-вызовы в Elixir.

## 1. Архитектура

Пакет `devtools/selfcheck/`, точка входа `python -m selfcheck`.

```
load (manifest, config) ─► plan run ─► collect (пробы) ─► normalize
    ─► correlate ─► judge (opt) ─► delta ─► report
```

- **Проба** — один внешний инструмент или один собственный анализатор. Вход —
  `RepoTarget` (абсолютный путь, `owner_repo`, языки, корпус §1.4) и каталог
  прогона; выход — `ProbeResult` (§4.1). Пробы не знают друг о друге.
- **Нормализация** приводит вывод к `Finding` (§2).
- **Корреляция** склеивает находки разных проб на один якорь (§2.1) и
  применяет allowlist (§2.4).
- **Дельта** сравнивает с базовым прогоном (§4.3).
- **Отчёт** — `out/selfcheck/<run_id>/report.{json,md}` в devtools (`out/`
  уже в `.gitignore`, поэтому отчёты не попадают в сканируемый корпус);
  `run_id` — UTC-метка `YYYYMMDDTHHMMSSZ`, повторные прогоны за день не
  перезаписывают друг друга. Отчёт, который владелец хочет сохранить в
  истории, копируется в `reports/` вручную.

### 1.1 Цели Makefile

| Цель | Что делает |
|---|---|
| `make selfcheck` | прогон на devtools (`ARGS`: `--fleet`, `--repo X`, `--judge`, `--sched-dir D`) |
| `make selfcheck-dogfood` | прогон на собственном пакете `selfcheck/` + фикстурные тесты |

Имя `selfcheck` принадлежит инструменту; прогон на себе — только
`selfcheck-dogfood`.

### 1.2 Набор репо и языки

Репо выводятся из `$(MANIFEST)`: записи секций `cores`, `apps`, `tools`
дедуплицируются по `git_dir` (записи с `member = true` делят каталог с
родителем). Число репо в спеке не фиксируется: отчёт печатает, сколько записей
прочитано, сколько уникальных `git_dir` просканировано; отсутствующий на диске
каталог — находка `selfcheck.repo-missing` и отметка неполноты флота (§3.2.4).

Языки — по файлам-маркерам в `git_dir`:

| Маркер | Язык | Пробы |
|---|---|---|
| `pyproject.toml` | Python | ruff, pyrefly, vulture, deptry, radon, ast-dup |
| `Cargo.toml` | Rust | clippy, cargo-machete |
| `mix.exs` | Elixir | credo, mix-xref |
| `package.json` | TS/JS | knip |
| любой | — | usage-graph, cli-overlap, llm-sites, shellcheck, actionlint, zizmor, jscpd |

Репо с несколькими маркерами получает объединение проб.

### 1.3 Контракт исполнения (read-only к целям)

- Инструментальное окружение принадлежит devtools: Python-инструменты —
  `uv run --project <devtools> --frozen --group selfcheck <tool>` (группа
  добавляется в `devtools/pyproject.toml` рядом с `dev`/`governance`);
  node-инструменты — `npx --yes <pkg>@<точная версия>`; системные бинари
  (`shellcheck`, `actionlint`, `zizmor`, `semgrep`, `cargo`, `mix`) — из `PATH`
  с проверкой версии по диапазону в реестре проб (§4.1).
- `cwd` каждой пробы — `out/selfcheck/<run_id>/work/<probe>/<repo>/`; цель
  передаётся абсолютным путём аргументом. Отчёты и кэши инструментов
  направляются туда же явными флагами/переменными (`--output`,
  `--cache-dir`, `RUFF_CACHE_DIR`, `CARGO_TARGET_DIR` и т. п. — точный набор
  фиксируется в реестре проб).
- Инструменты, пишущие в дерево цели при любых флагах (сборка Cargo/Mix для
  clippy, credo, `mix xref`), работают на **снимке**: `git -C <target>
  archive HEAD | tar -x -C <work>`. Снимок видит только закоммиченное —
  отчёт помечает такие пробы `scope: HEAD`.
- Страж: до и после прогона снимается `git -C <target> status --porcelain
  --ignored`; расхождение — находка `selfcheck.target-mutated` (high), статус
  нарушившей пробы — `failed`.

### 1.4 Корпус

Сканируется `git -C <target> ls-files --cached --others --exclude-standard`:
закоммиченное плюс неигнорируемое незакоммиченное. Игнорируемые файлы
(`.venv`, `out/`, установленные копии skills в
`devtools/.claude/skills/*` — `.gitignore` там) **не сканируются и не дают
рёбер**. Установленные skills представлены своим трекаемым исходником в
репо-владельце (`prograph-vault/authored/skills/`) — в `--fleet` он входит
в корпус как часть флота. Symlink'и не разыменовываются. Вне корпуса всегда:
`_cowork_output/` (не репо манифеста; правило корневого `CLAUDE.md`).

## 2. Находка

```json
{
  "id": "sc-3f9a1c2e",
  "rule": "dead.file",
  "category": "dead",
  "severity": "medium",
  "confidence": "candidate",
  "owner_repo": "fixture",
  "anchor": "file:scripts/unused_fixture.py",
  "discriminator": null,
  "location": {"path": "scripts/unused_fixture.py", "line": 1},
  "related": [],
  "sources": ["usage-graph", "vulture"],
  "evidence": [{"kind": "no-exec-edge", "detail": "…"}],
  "suggestion": "удалить или перенести в docs/archive",
  "judge": null
}
```

### 2.1 Идентичность

`id = "sc-" + sha1(rule | owner_repo | anchor | discriminator)[:8]`.

- `anchor` не содержит номеров строк: `file:<path>`, `func:<path>::<qualname>`,
  `make:<target>`, `skill:<name>`, `cmd:<name>`, `workflow:<file>#<job>`,
  `dup:<hash>`, `llm:<path>::<qualname>`. Строка — только в `location`.
- `discriminator` различает несколько находок одного правила на одном якоре
  (напр., два нарушения ruff в функции): порядковый номер вхождения внутри
  якоря; `null`, если вхождение одно.
- **Корреляция**: находки разных проб на один якорь склеиваются в одну; её
  `rule` — правило с наивысшим приоритетом по фиксированному порядку
  `usage-graph > ast-dup > vulture > <линтеры>`, `sources[]` — все пробы.
- **Межрепные и межфайловые дубли**: `anchor = dup:<hash>`; все участники —
  в `related[]` (`owner_repo`, `path`, `line`); `owner_repo` находки —
  владелец лексикографически первого участника. Ключ `(id, owner_repo)` —
  будущий ключ идемпотентного заведения issue.

### 2.2 Severity

bug от линтеров — по уровню инструмента; dead/duplicate — medium;
llm-replaceable — low; selfcheck.* — по таблице §4.

### 2.3 Уверенность

Общий default — `candidate`. Повышение — только по таблицам ниже; `confirmed`
означает «в заявленной и **полной** поверхности (§3.2.4) нет известных
статических потребителей», а не «код доказанно не нужен».

**dead** — решающая таблица, первая сработавшая строка:

| # | Условие | confidence |
|---|---|---|
| 1 | узел — корень (§3.2.2) | не dead; максимум `dead.root-stale` `candidate` (§3.2.2) |
| 2 | узел в зоне неразрешённого запуска (§3.2.3) | `candidate`, evidence `unresolved-exec` |
| 3 | поверхность неполна (§3.2.4) | не выше `likely` |
| 4 | класс `test-only` / `doc-only` | `candidate` |
| 5 | `orphan`, нет текстовых упоминаний имени в корпусе флота, последний коммит файла старше 60 дней | `confirmed` |
| 6 | `orphan`, иначе (есть текстовое упоминание, моложе 60 дней, нет git-истории) | `likely` |

Различие ребра `doc` и упоминания: ребро `doc` — путь к узлу в markdown
(ссылка или путь в тексте `*.md`, §3.2.1); упоминание — вхождение голого
имени файла где угодно в корпусе (код, конфиги, комментарии). Упоминание —
не ребро, а признак (evidence `mentioned-in`): узел с одними упоминаниями
остаётся `orphan` и попадает в строку 6, а не в `doc-only`.

**dead.symbol** (vulture, функции/классы/переменные внутри живого файла):
vulture confidence 100 → `likely`, ниже → `candidate`; `confirmed` не
присваивается. Символ в `orphan`-файле поглощается находкой файла (`sources`
получает `vulture`) и уверенность файла не повышает.

**duplicate**: exact-клон (§3.3, литералы сохранены) ≥ 8 строк —
`confirmed`; структурный клон (литералы стёрты) — `candidate`, различающиеся
литералы — в evidence; клон jscpd — `likely`; `cli-overlap` — `candidate`.

**llm-replaceable**: без судьи — `candidate`; судья может поднять до `likely`,
не выше.

### 2.4 Allowlist

`devtools/selfcheck.toml`, `[[allow]]` с полями `id` или `anchor`, `reason`,
`until` — **все обязательны** (запись без них — ошибка загрузки конфига,
код выхода 4). Истёкший `until` — находка `selfcheck.allow-expired`. Первая
запись — `issue_console.py` (неприкасаем по решению владельца: новый TUI —
новый файл). Allowlist подавляет находку в отчёте, но сохраняет её в JSON в
разделе `suppressed`.

## 3. Пробы

### 3.1 Линтеры (bug / quality / deps)

| Проба | Инструмент | Что берём |
|---|---|---|
| `ruff` | ruff, набор `F,B,PL,SIM,ERA,C90,ARG,RET` поверх конфигурации репо | bug/quality |
| `pyrefly` | pyrefly check | bug |
| `vulture` | vulture `--min-confidence 60` | dead.symbol |
| `deptry` | deptry | deps |
| `radon` | radon cc/mi | quality: ранг ≥ D |
| `shellcheck` | shellcheck `-f json` (файлы по расширению и по shebang) | bug |
| `actionlint`, `zizmor` | `-format '{{json .}}'`, `--format json` | bug/security в workflows |
| `jscpd` | jscpd `--reporters json --output <work>` | duplicate (текст) |
| S4: `clippy`, `cargo-machete`, `credo`, `mix-xref`, `knip` | — | по языку |

knip запускается только при наличии установленного `node_modules` в цели,
иначе — `unavailable` с причиной; зависимости selfcheck не ставит.

### 3.2 Граф использования (dead)

#### 3.2.1 Узлы и рёбра

**Узлы:** исполняемые файлы (`*.py` с `__main__`, `*.sh`, любой файл с
shebang, включая безрасширенные вроде `scripts/review/harness-claude`),
Python-модули, цели `Makefile`, skills (трекаемые `skills/*/SKILL.md`,
`.claude/skills/*/SKILL.md`), slash-команды (`.claude/commands/*.md`), jobs
workflows, CLI-имена из `[project.scripts]`.

**Рёбра** (тип, место, исполняемость):

| Тип | Источник | Исп. |
|---|---|---|
| `make` | рецепты `Makefile` | да |
| `ci` | `.github/workflows/*.yml`: `run:`, локальные `uses:` | да |
| `import` | Python-импорты (AST), `python -m pkg.mod` | да |
| `exec` | запуск с **разрешённой** целью (§3.2.3) из Python, shell, рецептов | да |
| `entry` | `uv run [--project D] <cli>` / вызов CLI-имени → функция из `[project.scripts]` проекта D | да |
| `skill` | упоминание пути/команды в трекаемом `SKILL.md` или команде | да |
| `sched` | systemd-юниты в корпусе (`**/*.service`, `*.timer`); launchd-плисты из `--sched-dir` | да |
| `runbook` | команда в fenced-блоке `sh`/`bash`/`console` внутри `README.md`/`docs/**` | да |
| `fleet` | любое исполняемое ребро из **другого** репо манифеста | да |
| `test` | `tests/**` | нет |
| `doc` | прочие ссылки в `*.md` (вне fenced-команд) | нет |

**Классы узла:** `live` — есть исполняемое ребро; `test-only`; `doc-only`;
`orphan` — рёбер нет.

#### 3.2.2 Корни

Корни — публичные точки входа, для которых отсутствие входящего вызова
нормально: цели `Makefile`, упомянутые в `help`; трекаемые skills и
slash-команды; jobs workflows; юниты расписаний; CLI-имена
`[project.scripts]`. Корень **никогда** не получает `dead`. Для корня
статически проверяется только:
- `broken-root` (bug, high): корень запускает несуществующий файл/цель/CLI;
- `dead.root-stale` (`candidate`): корень не менялся > 180 дней **и** его имя
  не упоминается нигде в корпусе флота, кроме места определения.

Фактическое использование корней (запускал ли кто-то цель) статически
недоказуемо; телеметрия запусков — вне объёма.

#### 3.2.3 Разрешение вычисляемых запусков

Резолвер понимает конечный набор форм и превращает их в `exec`-ребро:
- Python: `Path(__file__).with_name("x")`, `Path(__file__).parent / "x"`
  (любая цепочка `.parent` и `/` с литералами), `os.path.join(os.path.dirname(__file__), "x")`;
  argv, собранный списком и переданный в `subprocess.*` напрямую **или**
  через склейку в строку для `tmux new-session`/`sh -c` (пример —
  `issue_console.py`: `Path(__file__).with_name("issue_worker.py")` →
  `shlex.quote`-склейка → `tmux`);
- shell: `"$SCRIPT_DIR/x"`, `"$(dirname "$0")/x"`, `$(cd … && pwd)/x`, где
  переменная присвоена в том же файле литеральным выражением этих форм;
- обёртки: `uv run [--project D] X`, `python3 X`, `sh X`, `bash X`,
  `exec X`.

Запуск, цель которого не разрешилась (переменная из аргумента, чтение из
конфига, выбор по имени репо — напр., `review-pr.sh` → `"$trusted_kit_dir/local.sh"`),
порождает **зону неразрешённого запуска**: все узлы, совпадающие с
остаточным литеральным суффиксом (`*/local.sh`), а при его отсутствии — все
узлы каталога вызывающего файла, получают evidence `unresolved-exec` и
потолок `candidate` (§2.3, строка 2). То же — для `getattr`/
`importlib.import_module` с неконстантным аргументом, glob по каталогу с
последующим запуском и entry-points-регистрации (зона — пакет/каталог).
Правило консервативно: пропустить мёртвое дешевле, чем рекомендовать удалить
живое.

#### 3.2.4 Полнота поверхности

Каждый прогон фиксирует состояние источников в `run.surface`:
- `fleet`: `complete` (все `git_dir` манифеста прочитаны), `partial` (есть
  `repo-missing` или ошибки чтения), `absent` (прогон без `--fleet`);
- `sched`: `repo-units` всегда; `local-launchd:<host>:<N plists>` при
  `--sched-dir`; отсутствие каталога — `repo-units-only`;
- `history`: `git` / `none` (нет истории — возрастные условия не
  выполняются).

`confirmed` для dead возможен только при `fleet = complete` и `history = git`.
Полноту launchd доказать нельзя (машинно-локальны); поэтому отчёт всегда
печатает, какие плисты какого хоста учтены, а `confirmed` означает «нет
потребителей в перечисленных источниках». Следствие: в S1 (без `--fleet`)
dead выше `likely` не бывает.

### 3.3 Дубли по смыслу (duplicate)

- `ast-dup`: два хэша на функцию ≥ 8 строк —
  **exact** (стёрты только имена локальных переменных и докстринги) и
  **structural** (дополнительно стёрты строковые и числовые литералы).
  Совпадение exact → `confirmed`; только structural → `candidate`, различия
  литералов — в evidence (одинаковая структура с разными порогами/ключами
  протокола — часто разные политики, а не копия). Включая межрепные клоны
  (S3: «один хелпер в N репо → кандидат в общий пакет»).
- `cli-overlap`: скрипты с пересекающимися `argparse`-сигнатурами (≥ 80 %
  совпадающих флагов) и цели `Makefile` с идентичным рецептом после
  нормализации переменных.

### 3.4 LLM-вызовы (llm-replaceable)

**Точка вызова** — место в коде, которое непосредственно запускает модель:
вызов процесса с бинарём харнесса, вызов метода SDK-клиента, HTTP-запрос к
эндпоинту модели. Обёртка, передающая аргументы дальше, — не точка вызова, а
ребро к ней.

`llm-sites` ищет:
- A — бинарь харнесса (`claude`, `codex`, `opencode`, `aider`, `pi`, `qwen`,
  `ollama`, `llama-cli`, `copilot`) в Python-`subprocess` (AST) **и** в
  командных позициях shell-файлов, включая безрасширенные по shebang
  (пример — `scripts/review/harness-claude`);
- B — импорт/вызов SDK (`anthropic`, `openai`, LangChain) — Python; TS — S4;
- C — HTTP на `/v1/messages`, `/v1/chat/completions`, `/api/generate`,
  `/completion` — Python; TS — S4;
- D — описания без вызова (каталоги, конфиги) — в инвентарь, не в кандидаты.

Поиск — semgrep-правила `selfcheck/rules/llm.yml` (Python, bash; TS в S4)
плюс AST-досборка аргументов для Python. Elixir — вне объёма.

Эвристики кандидата (каждая — отдельный признак в evidence): ответ
разбирается в enum/bool/фиксированную JSON-схему; промпт — шаблон с
подстановкой коротких полей; вызов в цикле по однородным элементам; нет
свободного текста, уходящего человеку. Исключение: промпт содержит дифф,
код или документ целиком, либо результат — генерация текста/кода → точка
только в инвентаре.

## 4. Статусы проб и fail-closed на сам прибор

### 4.1 Контракт адаптера (реестр проб)

Каждая проба в реестре `selfcheck/probes.py` декларирует нормативно:
поддерживаемый диапазон версий; argv и формат вывода; множество нормальных
кодов выхода (зависит от версии — фиксируется для закреплённой); способ
получить **покрытие** — число входов, которые инструмент реально обработал
(из его вывода или, если инструмент не сообщает, сверкой: ожидаемые входы по
корпусу vs файлы, фигурирующие в выводе/статистике); путь к файлу вывода в
каталоге прогона.

`ProbeResult`: `status`, `tool_version`, `argv`, `exit_code`,
`inputs_expected`, `inputs_processed`, `diagnostics[]`, `findings[]`,
`duration`.

### 4.2 Статусы

| Статус | Условие |
|---|---|
| `ok` | версия в диапазоне; код в нормальном множестве; вывод — свежий файл этого прогона (mtime ≥ старта пробы) и разобрался; `inputs_processed = inputs_expected`; нет диагностик об ошибках разбора входов |
| `partial` | всё как `ok`, но часть входов не обработана или есть диагностики об ошибках разбора отдельных файлов (у собственных анализаторов — исключение на файле) |
| `failed` | код вне множества; вывод не разобрался / отсутствует / устарел; `inputs_processed = 0` при `inputs_expected > 0`; таймаут; исключение анализатора вне файла; нарушение §1.3 |
| `unavailable` | бинаря/пакета нет или версия вне диапазона (с причиной) |
| `skipped` | проба неприменима: язык не совпал **или** `inputs_expected = 0` (напр., нет workflows — вместо «нет входов» у zizmor) — с причиной |

Находки прибора: `failed` → `selfcheck.probe-failed` (high); `partial` →
`selfcheck.probe-partial` (medium) с перечнем пропущенных входов;
`unavailable` → `selfcheck.probe-unavailable` (medium).

Ожидаемые нормальные коды (подтверждаются тестом на закреплённой версии при
имплементации; источник истины — реестр + тест, не эта таблица): ruff 0/1;
pyrefly 0/1; vulture 0/3; deptry 0/1; shellcheck 0/1; actionlint 0/1; zizmor
по документации закреплённой версии (для 1.29: находки — 11–14, «нет входов»
— 3, что у нас исключено предварительным `skipped`); jscpd 0/1 **при
подтверждённом покрытии** (код 1 без JSON-отчёта — `failed`); knip 0/1;
credo — битовая маска категорий.

Собственные анализаторы (usage-graph, ast-dup, cli-overlap, llm-sites) и
semgrep подчиняются тому же контракту: покрытие — число разобранных файлов,
ошибка разбора файла — диагностика и `partial`.

### 4.3 Прогон, дельта и коды выхода

`run` в JSON: `run_id`, `scope` (репо, флаги), для каждого репо `HEAD` и
признак dirty, `surface` (§3.2.4), версии и конфиги проб, sha1
`selfcheck.toml`.

**Базовый прогон** — последний предыдущий в `out/selfcheck/`, чей `scope`
покрывает текущий. Для каждой находки базового прогона, отсутствующей
сейчас: `resolved` — только если та же проба на том же репо в обоих
прогонах `ok` и файл якоря есть в текущем корпусе (или удалён — тогда
`resolved: file-removed`); иначе `not-rechecked`. Новые — `new`.

Код выхода `selfcheck`: 0 — все пробы `ok`/`skipped`; 2 — есть `failed` или
`partial`; 3 — нет `failed`/`partial`, но есть `unavailable`; 4 — ошибка
манифеста, конфига или записи отчёта (отчёт не выпущен). Находки по коду сами
по себе код выхода не меняют.

## 5. Судья (`--judge`)

Выключен по умолчанию и в CI. Вход — находки `llm-replaceable` и
`duplicate` уровня `candidate`/`likely`.

**Граница полномочий.** Судья — вызов без инструментов и без доступа к
checkout'ам: единственный вход — сериализованный срез в stdin (функция
вызова ± 40 строк, промпт-шаблон, место разбора ответа; для дубля — оба
участника). Адаптер для S5 — только `claude`: `claude -p --output-format json
--json-schema <verdict> --restricted --strict-mcp-config
--no-session-persistence --permission-prompts none --tools ""`, `cwd` —
пустой временный каталог, `env` урезан до `PATH`/`HOME` (та же линза, что у
`scripts/review/harness-claude`, но с пустым набором tools). Другие харнессы
— `unavailable` до своего адаптера. Таймаут 120 с на кандидата, лимит вывода
64 КиБ.

**Выход** валидируется схемой: `{verdict: replace|keep|unsure,
replacement: regex|rules|decision-tree|embedding-classifier|small-model|merge|none,
rationale}`. Вердикт может менять только поле `judge` и уверенность в
пределах §2.3 (`replace` → `likely`; `keep` → перенос в раздел `info`); не
создаёт находок, не меняет `id`, `owner_repo`, scope. Невалидный ответ,
таймаут, ошибка — `judge: {verdict: "error", detail}`, находка остаётся как
была.

## 6. Тестирование

### 6.1 Фикстура

`tests/fixtures/selfcheck_repo/` — мини-git-репо (создаётся тестом из
шаблона, чтобы иметь историю и возраст коммитов) плюс соседнее мини-репо и
мини-манифест для `--fleet`:
- `orphan` старше 60 дней без упоминаний (`confirmed` только при `--fleet`
  complete; без — `likely`);
- скрипт, вызываемый только из launchd-плиста фикстурного `--sched-dir`
  (`live`); тот же без `--sched-dir` (`orphan`, не выше `likely`);
- **трудные вызывающие (отрицательные двойники dead):** worker, запускаемый
  через `Path(__file__).with_name()` + `tmux`-склейку; скрипт, запускаемый
  через `"$SCRIPT_DIR/x"`; `local.sh`, выбираемый вычисляемым каталогом
  (`unresolved-exec` → `candidate`); установочный скрипт из fenced-блока
  README (`runbook` → `live`); CLI через `uv run --project` и
  `[project.scripts]` (`entry` → `live`); безрасширенный shebang-скрипт;
  модуль через `importlib.import_module(name)`;
- skill и цель `Makefile` без входящих вызовов (корни — не dead); цель,
  вызывающая несуществующий скрипт (`broken-root`);
- exact-клоны; структурные клоны с разными порогами (`candidate`, не
  `confirmed`); похожие, но различающиеся функции (не дубль);
- LLM-вызов с разбором в enum (кандидат) и со свободной генерацией по диффу
  (не кандидат); вызов `claude` из shell-файла без расширения (в инвентаре);
- две цели `Makefile` с одинаковым рецептом и две — с разным;
- игнорируемый каталог со скриптом, вызывающим живой узел (ребро не
  учитывается).

### 6.2 Прибор

На каждую пробу: «находки есть, код в нормальном множестве → `ok`»;
«код 0, вывод не разобрался → `failed`»; «код 0, валидный пустой вывод при
`inputs_processed = 0 < inputs_expected` → `failed`»; «устаревший файл вывода
от прошлого прогона → `failed`»; «ошибка разбора одного файла → `partial`»;
«бинаря нет / версия вне диапазона → `unavailable`»; «нет входов → `skipped`».
Страж §1.3: проба, пишущая в цель, → `selfcheck.target-mutated`.

### 6.3 Идентичность, дельта, конфиг, судья

- вставка строк выше якоря не меняет `id`; два нарушения на одном якоре —
  разные `discriminator`;
- дельта: devtools-only прогон после `--fleet` не объявляет находки соседей
  `resolved` (`not-rechecked`); пропавший бинарь — `not-rechecked`;
- allowlist: истёкшая запись → `allow-expired`; запись без `reason` → код 4;
- судья мокается; без `--judge` харнесс не вызывается ни разу; argv адаптера
  содержит пустой `--tools` и `--restricted`; ответ, меняющий `id` или
  поднимающий до `confirmed`, отвергается;
- `uv run pytest`, `pyrefly check`, `ruff check`/`format` по `selfcheck/`;
  `make selfcheck-dogfood` зелёный.

## 8. Риски

- **Ложный «мёртвый»** — главный вред. Меры: корни не бывают dead; резолвер
  вычисляемых запусков + зоны неразрешённого запуска; `runbook`-рёбра;
  `confirmed` только на полной поверхности; фикстура трудных вызывающих.
- **Шум линтеров на старом коде** — отчёт группирует по правилу, показывает
  топ; дельта между прогонами важнее абсолютного числа.
- **Дрейф кодов выхода и форматов** при обновлении инструментов — версии в
  реестре, коды и покрытие закреплены тестами; выход за диапазон версий —
  `unavailable`, а не молчаливый неверный разбор.
- **Снимок `git archive` для Cargo/Mix не видит незакоммиченного** —
  отмечается `scope: HEAD` в сводной таблице.
