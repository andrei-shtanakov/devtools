# selfcheck: самодиагностика devtools и флота — баги, мёртвое, дубли, заменимые LLM-вызовы

Дата: 2026-09-25. Статус: **draft** — дизайн согласован с владельцем по секциям
в сессии 2026-09-25; ждёт локального Codex-цикла (spec-authoring, vault rule
`authored/rules/spec-authoring.md`). PR откроется один — на пару «спека + план».

Основания:
- запрос владельца: средство самодиагностики с упором на **предложения по
  упрощению** (неиспользуемые и дублированные скрипты/модули/цели), по максимуму
  на линтерах, скриптах и анализаторах; плюс проверка «можно ли LLM-вызов
  заменить скриптом, алгоритмом принятия решений или малой моделью»;
- инвентарь LLM-вызовов по флоту, снятый вручную 2026-09-02
  (`_cowork_output/2026-09-02-llm-invocation-inventory.md`, dev-only; служит
  только эталоном для приёмки, runtime его не читает) — четыре механики
  вызова A–D;
- набор репо — `workspace-manifest.toml` зонтика (`$(MANIFEST)` в `Makefile`).

## 0. Цель и границы

Инструмент `selfcheck` — детерминированный конвейер проб над репо, который
выдаёт **отчёт** (Markdown + JSON) с ранжированными находками пяти категорий:
баги/качество, мёртвое, дубли, зависимости, LLM-заменимые вызовы. Главная
ценность — категории «мёртвое» и «дубли» для скриптов `devtools/`, целей
`Makefile`, skills и slash-команд.

Критерии успеха:
1. `make selfcheck` на devtools выдаёт отчёт, где каждая проба видна в сводной
   таблице (инструмент, версия, код выхода, статус, число находок); упавшая
   проба — находка, а не тишина (§4);
2. каждый скрипт, цель `Makefile`, skill и slash-команда devtools получает
   класс использования (§3.2) с доказательствами-рёбрами;
3. находки имеют стабильный `id` и `owner_repo` — формат готов к последующему
   автозаведению issues без переделки (§2);
4. на фикстуре-мини-репо каждое правило срабатывает на своём случае и **не**
   срабатывает на отрицательном двойнике (§6);
5. LLM (`--judge`) не участвует в прогоне по умолчанию и видит только
   предотобранных кандидатов.

Вне объёма (S1–S5):
- автофиксы и автоудаление — инструмент советует, не правит;
- автозаведение issues (формат готов, механизм — отдельная арка);
- CI-гейт: подключение в CI решается после нескольких прогонов по доле
  ложных срабатываний;
- правка кода соседних репо: соседи сканируются **только на чтение**,
  находки по ним — в отчёт с `owner_repo` соседа.

## 1. Архитектура

Пакет `devtools/selfcheck/`, точка входа `python -m selfcheck`.

```
collect (пробы) ──► normalize (Finding) ──► correlate ──► judge (opt) ──► report
```

- **Проба** — один внешний инструмент или один собственный анализатор; на вход
  получает `RepoTarget` (путь, `owner_repo`, языки), на выход —
  `ProbeResult(status, tool_version, exit_code, findings)`. Пробы независимы и
  не знают друг о друге.
- **Нормализация** приводит вывод инструмента к `Finding` (§2).
- **Корреляция** склеивает находки разных проб на один якорь (напр., vulture
  «unused function» + граф «orphan» → одна находка, повышенная уверенность) и
  применяет allowlist (§2.3).
- **Судья** — только при `--judge` (§5).
- **Отчёт** — `reports/selfcheck/<YYYY-MM-DD>.{json,md}` в devtools; при повторном
  прогоне раздел «дельта» (новые / ушедшие `id` против предыдущего отчёта).

Внешние Python-инструменты пинуются в dependency-group `selfcheck` в
`devtools/pyproject.toml` и запускаются `uv run --frozen --group selfcheck`;
node-инструменты — `npx --yes <pkg>@<точная версия>`; системные бинари
(`shellcheck`, `actionlint`, `zizmor`, `cargo`, `mix`) берутся из `PATH`, их
отсутствие — статус `unavailable` (§4), не падение прогона.

### 1.1 Цели Makefile

| Цель | Что делает |
|---|---|
| `make selfcheck` | обычный прогон на devtools (`ARGS` — доп. флаги: `--fleet`, `--judge`, `--repo X`) |
| `make selfcheck-dogfood` | прогон инструмента на его собственном пакете `selfcheck/` + фикстурные тесты |

Имя `selfcheck` принадлежит инструменту; прогон на себе — только
`selfcheck-dogfood`, чтобы `make selfcheck` не читался двусмысленно.

### 1.2 Набор репо и языки

Список репо выводится из `$(MANIFEST)`: записи всех секций (`cores`, `apps`,
`tools`) **дедуплицируются по `git_dir`** (записи с `member = true` делят
каталог с родителем). Число репо в спеке не фиксируется — отчёт печатает,
сколько записей манифеста прочитано и сколько уникальных `git_dir` просканировано,
и перечисляет отсутствующие на диске каталоги как находку `selfcheck.repo-missing`.

Языки репо определяются по файлам-маркерам в `git_dir`, не хардкодом:

| Маркер | Язык | Пробы |
|---|---|---|
| `pyproject.toml` | Python | ruff, pyrefly, vulture, deptry, radon, ast-dup, usage-graph, llm-sites |
| `Cargo.toml` | Rust | clippy, cargo-machete |
| `mix.exs` | Elixir | credo, `mix xref` |
| `package.json` | TS/JS | knip |
| любой | — | shellcheck (`*.sh`), actionlint + zizmor (`.github/workflows`), jscpd |

Репо может иметь несколько маркеров (напр., Python + Rust) — получает объединение проб.

## 2. Схема находки

```json
{
  "id": "sc-3f9a1c2e",
  "rule": "dead.command.orphan",
  "category": "bug | quality | dead | duplicate | deps | llm-replaceable | selfcheck",
  "severity": "high | medium | low",
  "confidence": "confirmed | likely | candidate",
  "owner_repo": "devtools",
  "path": "salvage_scan.py",
  "anchor": "file:salvage_scan.py",
  "evidence": ["no callers: Makefile, workflows, skills, fleet", "last commit 2026-07-10"],
  "suggestion": "удалить или перенести в docs/archive",
  "source": "usage-graph",
  "judge": null
}
```

### 2.1 Стабильный id

`id = "sc-" + sha1(rule | owner_repo | path | anchor)[:8]`. `anchor` не содержит
номеров строк: это `file:<path>`, `func:<path>::<qualname>`,
`make:<target>`, `skill:<name>`, `workflow:<file>#<job>`. Строка для
кликабельности хранится отдельным полем `line` и в `id` не входит — правка
выше по файлу не меняет `id`. Ключ `(id, owner_repo)` — ключ идемпотентного
заведения issue в будущем.

### 2.2 Правила уверенности

**`dead`** (самая опасная рекомендация):

| Класс в графе (§3.2) | Доп. признаки | confidence |
|---|---|---|
| `orphan` | нет упоминания по имени во всём флоте **и** последний коммит файла старше 60 дней | `confirmed` |
| `orphan` | есть упоминание в `_cowork_output/`, `prograph-vault/`, памяти (только текст) | `likely` |
| `doc-only` / `test-only` | — | `candidate` |
| узел под динамической диспетчеризацией (§3.2) | — | не помечается мёртвым; флаг `dynamic-dispatch` |

**`duplicate`**: совпадение нормализованного AST-хэша функции ≥ 8 строк —
`confirmed`; клон jscpd — `likely`; совпадение `argparse`-сигнатуры или тела
цели `Makefile` — `candidate`.

**`llm-replaceable`**: без судьи — не выше `candidate`; с судьёй — не выше
`likely`. `confirmed` не присваивается никогда: решение за человеком.

### 2.3 Allowlist

`devtools/selfcheck.toml`, секция `[[allow]]` с полями `id` или `anchor`,
`reason`, `until` (дата) — **все обязательны**. Истёкший `until` превращает
запись в находку `selfcheck.allow-expired`. Первая запись — `issue_console.py`
(неприкасаем по решению владельца: новый TUI — новый файл).

## 3. Пробы

### 3.1 Линтеры (bug / quality / deps)

| Проба | Инструмент | Что берём |
|---|---|---|
| `ruff` | ruff, расширенный набор `F,B,PL,SIM,ERA,C90,ARG,RET` поверх конфигурации репо | bug/quality |
| `pyrefly` | pyrefly check | bug |
| `vulture` | vulture, `--min-confidence 60` | dead (функции/классы/переменные) |
| `deptry` | deptry | deps (неиспользуемые/незаявленные) |
| `radon` | radon cc/mi | quality: сложность ранга ≥ D |
| `shellcheck` | shellcheck `-f json` | bug |
| `actionlint`, `zizmor` | — | bug/security в workflows |
| `jscpd` | jscpd `--reporters json` | duplicate (текст любых форматов) |
| S4: `clippy`, `cargo-machete`, `credo`, `mix-xref`, `knip` | — | по языку |

### 3.2 Граф использования (dead)

**Узлы:** исполняемые скрипты (`*.py` с `__main__`/shebang, `*.sh`), Python-модули,
цели `Makefile`, skills (`skills/*/SKILL.md`, `.claude/skills/*/SKILL.md`),
slash-команды (`.claude/commands/*.md`), jobs workflows.

**Источники рёбер** (каждое ребро хранит тип и место):

| Тип ребра | Источник | Исполняемое? |
|---|---|---|
| `make` | рецепты `Makefile` | да |
| `ci` | `.github/workflows/*.yml` (`run:`, `uses:` локальных actions) | да |
| `import` | Python-импорты (AST) | да |
| `exec` | `subprocess`/`os.system` с литералом, shell-вызовы в `*.sh` | да |
| `skill` | упоминания в `SKILL.md` / командах | да (исполняет агент) |
| `sched` | launchd-плисты (`--sched-dir`, по умолчанию `~/Library/LaunchAgents/dev.atp.*`), systemd-юниты в репо (`deploy/**/*.service`) | да |
| `fleet` | любое из вышеперечисленных в **другом** репо манифеста | да |
| `test` | `tests/**` | нет |
| `doc` | `*.md` вне skills, docs, vault, `_cowork_output/` | нет |

launchd-плисты машинно-локальны: отчёт фиксирует, был ли прочитан `--sched-dir`
и сколько плистов в нём; при отсутствии каталога `dead`-находки не
поднимаются выше `likely` (исполнитель мог быть на другой машине).

**Классы узла:** `live` (есть исполняемое ребро), `test-only`, `doc-only`,
`orphan` (рёбер нет).

**Динамическая диспетчеризация:** узел помечается `dynamic-dispatch` и
выводится из-под `dead`, если в репо есть `getattr`/`importlib.import_module`
с неконстантным аргументом, glob по каталогу с последующим запуском, или
entry-points-регистрация, чей шаблон покрывает узел. Правило консервативно:
лучше пропустить мёртвое, чем рекомендовать удалить живое.

### 3.3 Дубли по смыслу (duplicate)

- `ast-dup`: хэш нормализованного AST функций (имена локальных переменных,
  строковые и числовые литералы, докстринги стёрты); одинаковый хэш в разных
  местах — клон, в том числе **между репо** (S3: «один хелпер в N репо →
  кандидат в общий пакет»).
- `cli-overlap`: скрипты с пересекающимися `argparse`-сигнатурами (≥ 80 %
  совпадающих флагов) и цели `Makefile` с идентичным рецептом после
  нормализации переменных.

### 3.4 LLM-вызовы (llm-replaceable)

`llm-sites` находит точки вызова по механикам инвентаря 2026-09-02:
A — `subprocess` с бинарём из списка харнессов (`claude`, `codex`, `opencode`,
`aider`, `pi`, `qwen`, `ollama`, `llama-cli`, `copilot`); B — импорт/вызов SDK
(`anthropic`, `openai`, LangChain); C — HTTP на известные эндпоинты
(`/v1/messages`, `/v1/chat/completions`, ollama); D — описания без вызова
(в инвентарь, но не в кандидаты). Поиск — semgrep-правила в
`selfcheck/rules/llm.yml` плюс AST-досборка аргументов.

Эвристики кандидата (каждая — отдельный признак в `evidence`):
- ответ разбирается в enum/bool/фиксированную JSON-схему (сравнение со
  списком строк, `json.loads` + обращение к фиксированным ключам);
- промпт — шаблон с подстановкой коротких полей, без вложения файлов/диффов;
- вызов внутри цикла по однородным элементам (классификация пакетом);
- на выходе нет свободного текста, который уходит человеку.

Признак-исключение: промпт содержит дифф, исходный код или документ целиком,
либо результат — генерация текста/кода → точка попадает в инвентарь, но не в
кандидаты. Инвентарь (все найденные точки) — отдельный раздел отчёта; приёмка
S1/S3 сверяет его с ручным инвентарём 2026-09-02.

## 4. Статусы проб и fail-closed на сам прибор

Ненулевой код выхода у линтера обычно значит «находки есть», а не «сломался».
Поэтому у каждой пробы в реестре задано **множество нормальных кодов**:

| Проба | Нормальные коды | Прочее |
|---|---|---|
| ruff | 0, 1 (есть нарушения) | 2 — ошибка |
| pyrefly | 0, 1 (есть ошибки типов) | прочее — ошибка |
| vulture | 0, 3 (найден мёртвый код) | 1, 2 — ошибка ввода/аргументов |
| deptry | 0, 1 | прочее |
| shellcheck | 0, 1 | 2–4 |
| actionlint | 0, 1 | 2, 3 |
| zizmor | 0, 10–14 (находки по уровням) | 1, 2 |
| jscpd | 0, 1 (порог превышен) | прочее |
| knip | 0, 1 | 2 |
| credo | 0 и битовая маска категорий < 128 | ≥ 128 |

Значения кодов проверяются на этапе имплементации по документации
закреплённой версии и фиксируются тестом на каждую пробу (§6); таблица выше —
ожидание, не источник истины.

Статусы пробы:
- `ok` — код в нормальном множестве **и** вывод разобрался;
- `failed` — код вне множества, **или** код нормальный, но вывод не разобрался
  (пустой/битый JSON при ожидаемом JSON, 0 находок при ненулевом «есть
  находки» коде), **или** таймаут;
- `unavailable` — бинаря нет в `PATH` / пакета нет в группе;
- `skipped` — проба не применима к языкам репо.

`failed` → находка `selfcheck.probe-failed` (severity high);
`unavailable` → `selfcheck.probe-unavailable` (medium). Сводная таблица проб —
первый раздел отчёта. Процесс `selfcheck` завершается с кодом 0, если все
пробы `ok`/`skipped`, и 2 — если есть `failed` (для будущего CI); находки
по коду сами по себе код выхода не меняют.

## 5. Судья (`--judge`)

Только при флаге; в CI и по умолчанию выключен. Вход — находки
`llm-replaceable` и `duplicate` уровня `candidate`/`likely`; каждому кандидату
подаётся **узкий срез**: функция вызова ± 40 строк, промпт-шаблон, место
разбора ответа. Выход — `judge = {verdict: replace|keep|unsure, replacement:
regex|rules|decision-tree|embedding-classifier|small-model|merge|none,
rationale}`; `replace` повышает до `likely`, `keep` понижает в `info`-раздел.
Исполнитель — CLI-харнесс по конфигу (`claude -p --output-format json` по
умолчанию), модель — из конфига `selfcheck.toml`. Сбой судьи на кандидате —
`judge: {verdict: "error"}`, находка остаётся с исходной уверенностью.

## 6. Тестирование

- **Фикстура** `tests/fixtures/selfcheck_repo/` — мини-репо с известным ответом:
  - мёртвый скрипт (`orphan`) и скрипт, вызываемый **только** из launchd-плиста
    фикстурного `--sched-dir` (должен быть `live`);
  - скрипт, на который ссылается только README (`doc-only`);
  - модуль, загружаемый через `importlib.import_module(name)` (не `dead`,
    `dynamic-dispatch`);
  - пара AST-клонов и пара похожих, но различающихся функций (отрицательный
    двойник);
  - LLM-вызов, классифицирующий в enum (кандидат), и вызов со свободной
    генерацией по диффу (не кандидат);
  - две цели `Makefile` с одинаковым рецептом и две — с разным.
- **Статусы проб:** на каждую пробу тест «находки есть, код ненулевой из
  нормального множества → `ok`, не `failed`» (отрицательный двойник к
  fail-closed) и тест «код 0, вывод не разобрался → `failed`»; тест
  «бинаря нет → `unavailable`».
- **Стабильность id:** вставка строк выше якоря не меняет `id`.
- **Allowlist:** истёкшая запись → `selfcheck.allow-expired`; запись без
  `reason` → ошибка загрузки конфига.
- **Судья** мокается; тест, что без `--judge` харнесс не вызывается ни разу.
- `uv run pytest`, `pyrefly check`, `ruff check`/`format` по `selfcheck/`;
  `make selfcheck-dogfood` зелёный.

## 8. Риски

- **Ложный «мёртвый»** — главный вред инструмента. Меры: исполняемые рёбра
  из шести источников, `dynamic-dispatch`, понижение без `--sched-dir`,
  `confirmed` только при отсутствии упоминаний во всём флоте + возраст.
- **Шум линтеров на старом коде** — расширенный набор ruff даст сотни находок.
  Отчёт группирует по правилу и показывает топ; дельта между прогонами важнее
  абсолютного числа.
- **Дрейф кодов выхода при обновлении инструментов** — коды закреплены тестами
  на закреплённых версиях; bump версии прогоняет эти тесты.
