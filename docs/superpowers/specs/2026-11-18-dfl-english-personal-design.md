# dfl по-английски: личный путь (#769, срез 1)

Дата: 2026-11-18. Issue: devtools#769. Статус: дизайн на одобрение владельца.

## Зачем

Владельцу нужен демонстрационный прогон `dfl` на английском — личный путь,
от вопроса трека до влитого PR. Дедлайн демо — 2026-11-26; после кода нужны
дни на живой прогон, файлы и ролики, поэтому код должен быть готов к
2026-11-23 (живой английский прогон на демо-проекте — в этот день).

Это первый срез #769: механизм выбора языка и каталог строк, покрывающие
**только личный путь**. Enterprise-путь, документация и `--help` — следующие
срезы тем же механизмом.

## Цели

- Прогон личного пути с `language=en` показывает в терминале только
  английский текст: вопрос трека, интервью, паузы просмотра, вопросы
  `dfl pending` / `dfl reply`, разбор edge-check, ручные проверки, остановки,
  прогресс, `dfl status`, отказы.
- Артефакты, которые пишут агенты, — на английском: бриф, дизайн,
  декомпозиция, замечания edge-check, `tasks.md` (человеческие строки),
  описание PR, issues ручных проверок.
- Русский режим — байт в байт прежний (умолчание).

## Не цели

- Enterprise-путь (`governance/*` вне перечисленного ниже), `dfl answer`,
  `interview`, `correct`, `init-repo`, `report`.
- `--help` argparse, README и руководство — по-русски до следующего среза.
- Вывод соседей (spec-runner, discovery): в личном прогоне он уходит в лог
  (`_QuietOps`), на экране — только при `DFL_VERBOSITY=3`. Не трогаем.
- Смена языка посреди прогона.

## Анти-цели

- Русский прогон, изменившийся хоть в одной строке.
- Английский режим, который ломает разбор: ответ «next» не принят,
  декомпозиция на английском не проходит проверку структуры, `tasks.md` не
  читается spec-runner.
- Две версии одного сообщения, разъезжающиеся без теста.

## Подходы (выбран 1)

1. **Каталог строк для личного пути** (выбран владельцем 18.11): сообщения
   оборачиваются в перевод, ключ — русский шаблон, английский текст — в
   словаре; промпты агентов — английские варианты файлов; тест полноты.
2. Полный каталог по всему dfl — правильно для #769 целиком, но не успеть
   к демо.
3. Перевод строк на выходе (в `say`) — ломается на подстановках, техдолг.

## Дизайн

### Выбор языка

- Флаг `dfl run --lang en|ru` на **новом** прогоне и переменная `DFL_LANG`
  (флаг сильнее). Умолчание — `ru`.
- Язык записывается в `PersonalRun.language` при создании прогона и дальше
  берётся только оттуда: `run` (продолжение), `pending`, `reply`, `status`,
  `abandon` читают язык прогона, флаг на продолжении игнорируется (если
  отличается — одна строка-предупреждение на языке прогона).
- Вопрос трека (`_ask_track`) задаётся до создания прогона — на языке флага
  или `DFL_LANG`.
- Ключ `language` в конфиге DarkFactory — **не в этом срезе**:
  `governance/df_config.py` под authority-root (мерж человека), а флага и
  env для демо достаточно.

### Каталог строк

- Модуль `lite/i18n.py`: `t(template: str) -> str` — возвращает перевод
  шаблона для текущего языка, иначе сам шаблон. Текущий язык — модульная
  переменная с `set_language(lang)`, выставляется в точке входа команды
  (`run`, `pending`, `reply`, `status`, `abandon`) после загрузки прогона.
- Словарь `lite/i18n_en.py`: `EN: dict[str, str]` — русский шаблон →
  английский. Шаблоны с `{name}` переводятся до `.format()`; плейсхолдеры
  в переводе — тот же набор (проверяет тест).
- Оборачиваются константы и литералы, которые печатает личный путь
  (разведка 18.11): `lite/personal/*`, личная часть `lite/dfl.py`,
  `lite/output.py` (`refusal`), `lite/pending.py`, `lite/review_pause.py`,
  `lite/owner_review.py`, `lite/edge_resolve.py` (личная часть),
  `lite/manual_ask.py`, `lite/interview_chat.py` (ввод),
  `governance/manual_checks.py` (вопросы, тела issues/комментариев),
  `governance/run_resume.py`, `governance/run_progress.py`,
  `governance/auto_tasks.py` (`notice`, `TUI_HINT`),
  `governance/review_remarks.py` (метки этапов, раздел PR),
  `governance/decomposition_guard.py` (сообщения `graph_findings`, видимые
  на личном пути). Ни один из этих файлов не под authority-root —
  проверить перед планом по `contracts/authority-root/v1/paths.env`.
- Константы, которые сейчас вычисляются при импорте (`X = "…"`), остаются
  русскими шаблонами; перевод — в месте использования (`t(X)`), чтобы язык
  выставлялся после импорта.

### Слова ответа

- Английские слова принимаются **в обоих режимах** (проще, и копия
  английского ответа в русском прогоне не ломает его):
  - «дальше» / «да» / «ок» / «1» → плюс `next`, `yes`, `ok`, `done`;
  - удалить / снять / принять / оставить → `remove`, `drop`, `accept`, `keep`;
  - «своё:» / «не согласен:» → плюс `own:`, `disagree:`;
  - `/стоп` → плюс `/stop`; «пропустить» / «не знаю» → `skip`, `don't know`;
  - «поправить:» в интервью → плюс `fix:`;
  - вердикты ручных проверок → `passed`, `failed`, `passed with caveat`.
- Подсказки ответа (`accepts`, тексты вариантов) показывают слова языка
  прогона.
- id вопроса (`sha256(text)`) зависит от текста — язык фиксирован на прогон,
  поэтому id стабильны.

### Промпты и артефакты

- Английские варианты: `lite/personal/prompts/en/{interviewer,design,
  decomposition}.md`. Загрузчики (`interviewer.PROMPT_PATH`,
  `nodes.PROMPTS`) выбирают каталог по языку прогона. Заголовки, которые
  добавляет код (`nodes.build_prompt`, `revise_prompt`, «## Режим правки»,
  «Решение заказчика»), — через каталог.
- Машинная грамматика не переводится: id (G/FR/D/DT/BEH), `#### D-NN:`,
  `**checked_by**`, `scenarios:`, `depends_on:`, `type: implement`,
  `owner: dev`. Две русские метки, которые читает код
  (`**Критерии:**`, `## Проверки` в `personal/check.py`), получают
  английские пары (`**Criteria:**`, `## Checks`); разбор принимает обе.
  Английский промпт декомпозиции просит английские.
- Бриф: заголовки `render_brief` — через каталог; язык значений задаёт
  английский промпт интервьюера.
- Edge-check: каталог контрактов `contracts/edge-check/v1-en/` —
  `instruction.md`, `response-schema.json` (копия), правила только личного
  пути. Выбор каталога — в трёх местах (`personal/check.py`,
  `nodes.py`, `edge_resolve.py`). Новый identity проверки ожидаем. Заголовки
  `governance/edge_check/prompt.py` — по языку. Промпт сортировки
  (`edge_triage.build_prompt`) — английский вариант.
- `tasks.md`: шапку рендерит `task_bridge`; личный путь уже подменяет в ней
  строку (`lite/personal/tasks.py`). Человеческие строки шапки в
  английском режиме заменяются там же; грамматика задач не меняется.
- Описание PR и issues ручных проверок — через каталог.

### Тест полноты

- Набор сценариев личного пути (существующие тесты flow/pause/pending/edge/
  manual, параметризованные `language="en"`) с проверкой: в захваченном
  выводе нет кириллицы, кроме текста, который ввёл сам пользователь или
  вернул фейковый агент.
- Тест словаря: каждый ключ `EN` встречается литералом в коде (нет
  мёртвых), плейсхолдеры ключа и перевода совпадают.
- Русский режим: существующий набор зелёный без правок.

### Ответы проверки читателем (18.11)

- **Что код читает обратно.** Полный список разбираемого русского на личном
  пути:
  - слова ответа (раздел выше);
  - метки `**Критерии:**` / `## Проверки` (`personal/check.py`);
  - префиксы ожидания `manual_ask.is_wait`: «ждёт ответа: », «ждут ответа»,
    `PAUSED` — `is_wait` принимает оба языка;
  - строка шапки `_DRAFT_SENTENCE` в `lite/personal/tasks.py`.

  Маркеры комментариев и issues ручных проверок (`comment_marker`,
  `issue_marker`) и `_WAIVED` — грамматика, не переводятся.
  `review_remarks` текст не разбирает. Остальное переводится свободно.
- **edge-check `v1-en`.** `response-schema.json` без кириллицы — байтовая
  копия. `instruction.md` и два правила личного пути
  (`personal-design-vs-brief.yaml`,
  `personal-decomposition-vs-design-brief.yaml`) — перевод; правил
  enterprise в `v1-en` нет. В `lite` identity проверки ни с чем закреплённым
  не сверяется; enterprise и `edge_check.py` остаются на `v1`.
- **Передача языка.** Агенты (автор, проверка, сортировка, интервьюер) —
  дочерние процессы, получающие готовый текст промпта. Поэтому язык
  промптов и каталогов контрактов передаётся явно аргументом из
  `run.language`, а не глобальным. `t()` с модульным языком — только для
  сообщений, печатаемых в процессе `dfl`.
- **Тесты.** Существующие тесты не трогаем: русский — умолчание. Английские
  сценарии — новый файл с англоязычными фейковыми агентами. Тест кириллицы
  строгий над этим набором сценариев (демо-путь плюс остановки и `pending`,
  `reply`, `status`); вне набора не утверждаем.
- **Запасной вариант.** Решение о сужении принимаю к 21.11 и сообщаю
  владельцу. Вливается срез только с зелёным строгим тестом над тем набором,
  который успели; списка исключений в тесте нет.

## Что оставлено исполнителю

- Точный список литералов по модулям (разведка дала счётчики, не список).
- Формулировки английского текста (простые, нейтральные; владелец
  вычитает демо-путь при живом прогоне).
- Как именно параметризовать существующие тесты (фикстура языка).

## Риски

- Объём: ~600–800 строк на личном пути. Если к 21.11 не укладываемся —
  приоритет экрану демо-сценария (трек → интервью → пауза → reply →
  edge → код → ручные проверки → PR), остальное фоллбэком по-русски.
- Модель может писать по-русски, если основание (бриф) русское — для демо
  бриф будет английским.
