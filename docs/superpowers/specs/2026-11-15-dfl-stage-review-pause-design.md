# dfl: пауза на просмотр артефакта после этапа — дизайн

Дата: 2026-11-15. Статус: на одобрение владельца (обсуждено 15.11; уточнения строителя — §7).
Связано: devtools#768 (запрос владельца), #764 / PR #774 (личный путь: этапы
бриф, дизайн, декомпозиция), #762 (разбор замечаний edge-check: агент
переписывает узел, вопросы — с вариантами).

## 1. Зачем

Сейчас документ этапа человек видит либо никогда (личный путь: бриф → дизайн →
декомпозиция идут без остановок до PR), либо уже в PR этапа (enterprise: волна
открывает candidate-PR, человек одобряет). Владелец: «нужна настройка, когда
после каждого этапа произведённый артефакт будет доступен для ревью»; «открыть
файл в редакторе и написать замечания своими словами, для этого в терминале
должна появиться ссылка на файл с подсказкой»; замечания — «в терминале, как в
интервью»; на enterprise — тоже, «желательно с ссылкой на документ, чтобы не
идти сразу читать PR».

## 2. Цели, не-цели, анти-цели

Цели:
- Необязательная пауза после этапа на обоих путях: документ уже прошёл
  edge-check, человек открывает его по ссылке, пишет замечания в терминале
  своими словами или говорит «дальше».
- По замечаниям агент сам переписывает документ, edge-check проходит заново,
  пауза повторяется — сколько угодно кругов, до «дальше».
- Настройка: какие этапы с паузой — умолчанием в конфиге DarkFactory и
  флагом на один прогон.

Не-цели:
- Правка документа человеком вручную как основной сценарий (можно, но
  пауза его не требует и не предполагает).
- Замечания в самом файле (комментарии-строки) — отклонено владельцем.
- Изменение порядка этапов, правил edge-check, человеческих актов enterprise
  (одобрение волны/PR остаётся как есть).

Анти-цели (провал, даже если «работает»):
- Пауза превращает процесс в экзамен: требует разметки, ID, формы ответа.
- Замечание человека молча удаляет содержимое документа.
- Пауза включена «по умолчанию» и тормозит тех, кто её не просил.
- Пауза пропускается без терминала молча (человек думал, что посмотрит, а
  конвейер ушёл дальше).

## 3. Как сейчас (факты)

- Личный путь (`lite/personal/flow.py`, PR #774): шаги `interview` → `design`
  → `decomposition` → `spec-pr` → `code-run` → `code-pr`; узел: автор →
  `check_node` (edge-check) → разбор замечаний `edge_resolve.resolve_scope` до
  `MAX_ROUNDS`; переписывание — `nodes.revise_node(call, kind, subject,
  current, findings, decisions)`; бриф подтверждается в разговоре («Верно?»).
- Enterprise (`governance/runner.py`, волны): авторинг узлов уровня → коммит →
  гейт → `_step_edge` → candidate-PR волны → одобрение человеком; стоп
  `stopped_review` и разбор замечаний в `lite/dfl.py` (`_resolve_rounds`,
  `edge_resolve.resolve`), `resume` из `stopped_review` сбрасывает
  `commit/gate-candidate/edge` (`runner.py:842`), т.е. переписанный узел
  проходит гейт и edge-check заново. Переписывание —
  `RealOps.revise(call, kind, subject, current, findings, decisions)`.
- Гвард «переписывание не ослабило узел» — `lite/node_guard.weakened(before,
  after, removes, downgrades)`.
- Конфиг DarkFactory — `governance/df_config.py` (**authority-root**, мерж
  человеком).

## 4. Решения

### 4.1 Где встаёт пауза

Пауза — после того как документ этапа прошёл edge-check (вердикт PASS или
принят вопреки по #762) и до следующего шага:

- Личный путь: этапы `brief`, `design`, `decomposition`. Для `brief` пауза — после
  записи `00-brief.md` (бриф уже подтверждён «Верно?»; пауза даёт открыть сам
  файл); для `design`/`decomposition` — после PASS edge-check, до следующего
  узла / spec-PR.
- Enterprise: этапы = узлы бандла `charter`, `requirements`, `behaviour-spec`,
  `design`, `acceptance`, `decomposition`. Пауза — после PASS edge-check
  волны, **до** открытия candidate-PR: в PR уходит уже поправленный документ.
  В волне из двух узлов (W4: design + acceptance) пауза показывает оба файла
  подряд, по одному.

### 4.2 Что видит человек

```
этап «дизайн» готов и прошёл проверку — посмотрите:
  file:///…/workstreams/<ws>/spec/20-design.md
замечания своими словами (пустая строка — отправить); «дальше» — без замечаний; /стоп — прервать
>
```

Ссылка — абсолютный путь `file://` (терминалы делают её кликабельной), строка
выводится на экран и под перехватом вывода `dfl` (как подсказка `spec-runner
tui`, `auto_tasks.notice`). Ввод — тот же, что в интервью (`read_answer`):
многострочный ответ до пустой строки; «дальше» (и «да», «ок», «1») — одной
строкой, без пустой.

### 4.3 Круг замечаний

1. Замечания пишутся в журнал прогона (строка: этап, текст, время).
2. Агент переписывает документ: тот же вызов, что разбор замечаний
   (`revise_node` / `RealOps.revise`), где замечания человека передаются как
   решения (`decisions`), находок edge-check нет.
3. Гвард ослабления: если переписанный документ удаляет или понижает пункты
   (id), `dfl` не принимает молча — вопрос с вариантами по каждому:
   «удалить D-02 (<название>)? 1. да · 2. нет». «Нет» — документ
   восстанавливается, агенту уходит ещё раз с пометкой «D-02 не удалять».
4. Edge-check документа заново (и разбор его замечаний по #762).
5. Снова пауза со ссылкой. Кругов — без ограничения, пока человек не скажет
   «дальше» (каждый круг — платные вызовы; их число печатается).

Замечания и их итог попадают в описание PR этапа (enterprise: candidate-PR
волны; личный путь: spec-PR) — раздел «Замечания владельца».

### 4.4 Включение

- Умолчание — в конфиге DarkFactory: `[review] pause_after = ["design", …]`
  (имена этапов из 4.1; пусто или нет ключа — пауз нет). Требует поля в
  `governance/df_config.py` — **authority-root**, отдельный маленький PR с
  мержем человеком.
- Флаг одного прогона: `dfl run --review <этапы>` — список через запятую,
  `all` (все этапы пути) или `none`; флаг сильнее конфига. Запоминается в
  состоянии прогона при старте и не меняется до конца (как `--track`).
- Неизвестное имя этапа — отказ с перечнем допустимых для этого пути.

### 4.5 Без терминала и при прерывании

- Без терминала пауза не пропускается: прогон останавливается со статусом
  «ждёт просмотра этапа <этап>» и подсказкой «откройте <ссылка>; замечания —
  `dfl run` в терминале».
- `/стоп`, Ctrl-C, Ctrl-D на паузе — пауза, не сбой (код 0); следующий
  `dfl run` снова показывает ту же ссылку и подсказку; уже отправленные
  замечания не повторяются.

## 5. Ограничения

- `governance/df_config.py` — authority-root: поле `review.pause_after` —
  отдельным PR, мерж человеком; остальное (`lite/`, `governance/runner.py`,
  `governance/run_state.py`, тесты) — обычные PR.
- Enterprise-поведение без включённой паузы — побайтово прежнее.
- Только режим `test` (как весь `dfl`).

## 6. Решения за строителем

- Имя статуса остановки enterprise-прогона на паузе и как `resume` из него
  повторяет edge-check (по образцу `stopped_review` → сброс
  `commit/gate-candidate/edge`).
- Формат строки журнала замечаний и раздела в описании PR.
- Как именно в промпт переписывания передаются замечания (в рамках
  `decisions`).

## 7. Уточнения после чтения строителем (мои решения)

1. **Интерактив — в `dfl`, раннер только останавливается.** Список этапов с
   паузой пишет в состояние прогона `dfl` при старте (`--review` / конфиг).
   Прогон, запущенный не через `dfl` (`make behaviour-run`), получает пустой
   список — пауз нет, поведение прежнее. Раннер на включённом этапе после PASS
   edge-check останавливается новым статусом (имя — за строителем); цикл
   замечаний целиком в `dfl` (по образцу `stopped_review` → `_resolve_rounds`).
2. **Enterprise: документ — в рабочем дереве ветки волны** (ссылка на него).
   Переписанный файл попадает в ветку через `resume`: сброс
   `commit/gate-candidate/edge` — коммит, гейт и edge-check заново;
   `source_sha` заявки волны берётся после последнего круга.
3. **Состояние:** новое поле прогона с пустым умолчанием, без смены версии
   схемы (как прочие поля с умолчанием); старые леджеры читаются как прежде.
4. **Порядок:** строится после мержа PR #774 (личный путь); поле конфига
   (authority-root) — отдельным маленьким PR параллельно; флаг `--review`
   работает и без него.
5. **Имена этапов в конфиге:** имя, неизвестное обоим путям, — отказ при
   загрузке конфига; имя, чужое текущему пути (`brief` на enterprise,
   `charter` на личном), молча не действует (конфиг общий). Во флаге — отказ
   с перечнем допустимых для пути.
6. **Гвард ослабления:** узлы с id (`#### D-NN`, `FR`, `NFR`, BEH, DT…) —
   `node_guard.weakened` после переписывания, удалённые/пониженные id —
   вопрос с вариантами до принятия файла. Бриф личного пути не переписывается
   автором: замечание к нему идёт интервьюеру как правка («2. поправить»),
   бриф пересобирается из JSON и снова подтверждается; удалённые G/FR видны
   при подтверждении. Текст без id (абзацы, разделы) гвардом не охраняется —
   правка по замечанию человека.
7. **Прерывание посреди круга:** замечания пишутся в журнал со статусом
   «не применены»; `dfl run` доигрывает круг по ним (переписать → проверить),
   повторно их не спрашивает; применённые помечаются.
8. **Волна из двух узлов (W4):** после правки любого узла волна проверяется
   целиком (оба ребра), пауза снова показывает оба файла.
9. **«Дальше»:** только целая строка (без регистра) — «дальше», «да», «ок»,
   «1»; «да, но …» — замечание.
10. **Без лимита кругов:** внутри круга разбор замечаний edge-check ограничен
    `MAX_ROUNDS` (#762); не сошлось — обычный стоп разбора.

## 8. Мои решения (не обсуждались — проверить)

- Пауза — после edge-check (документ уже согласован с основаниями), а не до.
- «Дальше» принимает и «да», «ок», «1».
- Удаление пунктов по замечанию — только с подтверждением вариантом.
- Кругов без ограничения; число платных вызовов печатается.
- Замечания — в журнал прогона и в описание PR этапа.
- Без терминала — стоп, не пропуск.
- Пауза после брифа на личном пути — да, хотя бриф уже подтверждён в разговоре
  (даёт открыть файл целиком).
