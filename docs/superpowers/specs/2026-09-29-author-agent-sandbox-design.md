# Песочница авторского агента — дизайн (devtools#469 п.2)

**Статус:** дизайн, **rev 3, 2026-10-11 — на ревью**. Rev 2 (2026-09-29) одобрен
владельцем; rev 3 вносит требования владельца 2026-10-11 и пробы осуществимости
того же дня (§11–§18, F14–F28). Номера §1–§10 сохранены — на них ссылаются код
и tasks-спека; разделы, которые rev 3 заменяет, помечены на месте. Tasks-спека
(`spec/author-agent-sandbox-tasks.md`) пересматривается после одобрения rev 3.
TODO: `author-agent-sandbox`.

**Цель.** Настоящая граница записи и чтения для агентов, которых запускает
раннер на стадии авторинга. Сегодня её нет: `claude --dangerously-skip-permissions`
пишет и читает что угодно по абсолютному пути, и вся локальная защита
edge-check упирается в потолок «двух согласованных артефактов»
(devtools#469, #478). Трипвайр #470 остаётся — он ловит запись в своё окно,
песочница её предотвращает.

**Это песочница с ограниченными гарантиями, не полная изоляция агента.** Она
закрывает запись вне собственного каталога вызова (файл узла в бандл переносит
раннер), чтение учётных данных GitHub и проверенные каналы выхода из неё
(launchd, cron, LaunchServices). Она **не** закрывает
чтение прочих секретов, сеть, GitHub API через найденный агентом токен и
содержимое самого узла — полный перечень с последствиями в §17, и никакой
текст, ссылающийся на песочницу, не вправе обещать больше.

## 2. Нативная песочница харнесса или внешняя обёртка

| | Нативная (Claude Code sandbox, codex `--sandbox`) | Внешняя (`sandbox-exec` вокруг процесса) |
|---|---|---|
| Что ограничено | Claude: только Bash-команды; **файловые инструменты (Read/Write/Edit) — нет**. Codex: запись рабочим каталогом, чтение — не ограничено | весь процесс и все потомки, все инструменты |
| Где задаётся | Claude: `.claude/settings.json` в проекте — **агент может его править**; codex: флаг | профиль у раннера, вне дерева цели |
| Связка ключей | Claude: документация молчит; codex: не установлено | запрещается `mach-lookup` (F6) |
| Кода у нас | меньше | профиль + обёртка + проба |
| Риск | доверие харнессу, у каждого своя модель | F10 (DEPRECATED) |

> **rev 3:** абзац ниже про codex под обёрткой с `danger-full-access` отменён
> решением владельца 2026-10-11 (Q1, §13): в v1 авторинг codex — отказ.

**Решение: внешняя обёртка.** Нативная у claude не закрывает главного —
файловые инструменты и чтение токенов, а конфиг достижим агенту. Следствие
F9: у codex собственный `--sandbox workspace-write` внутри обёртки не
запустится — под обёрткой codex идёт с `--sandbox danger-full-access`,
ограничение целиком снаружи (одна модель для обоих харнессов). **Это
ослабление, а не перенос один в один:** `workspace-write` закрывает codex
сеть (F13), а под обёрткой сеть открыта (§3). Для claude сеть открыта и
сегодня; для codex v1 сеть открывает — названо и принято вместе с §3.

**Отказ обёртки — стоп, не предупреждение.** Нет бинаря `sandbox-exec`,
профиль не применился, проба (§4) не прошла — раннер не запускает агента
вовсе (`stopped_author` с причиной). Запуска «без обёртки, с
предупреждением» не существует: это вернуло бы ровно сегодняшнее
состояние под видом защищённого.

## 3. Модель доступа (профиль Seatbelt)

> **rev 3:** правила записи этого раздела заменены §12 — агент пишет только в
> свежий каталог вызова (заготовка + временные), файл узла в бандл переносит
> раннер (§15); путь трекинга cwd не открывается (`CLAUDE_CODE_TMPDIR`);
> добавлен mach-запрет LaunchServices; disp и codex — §11, §13. Чтение, env и
> учётные данные модели — без изменений.

База — `(allow default)` с запретами (как в замере), а не `(deny default)`:
пустой разрешающий список для node/codex/uv неизвестен до спайков (§7), и
`deny default` дал бы песочницу, запрещающую работу. Граница задаётся
запретами:

**Запись** — запрещена всюду, кроме:
- `target_dir` (дерево цели — туда автор пишет узел; `.git` внутри);
- у disp — каталог анкера P9 прогона (`run_dir/disp-anchors` либо
  XDG-state, `_pinned_disp_anchor_dir`);
- **свой временный каталог вызова** (`TMPDIR` = `run_dir/agent-tmp/<call>`);
  `/private/tmp` и `/private/var/folders` целиком НЕ разрешаются (F11);
- собственное состояние харнесса — перечень устанавливает спайк S1/S2
  (`~/.claude*`, `~/.codex/sessions`, кэш `uv` для disp); каждый путь — с
  обоснованием в профиле.

`run_dir/edge-check/` и остальной каталог прогона агенту **не пишутся**.

**Чтение** — запрещено: `~/.config/review`, `~/.config/gh`,
`~/.config/ai-prosto`, `~/.ssh`. **Связка ключей** — запрет `mach-lookup`
к трём сервисам (F6).

**Окружение — allowlist, не наследование** (F12). Раннер собирает env
вызова с нуля из закрытого перечня: `PATH`, `HOME`, `USER`, `LANG`/`LC_*`,
`TMPDIR` (свой, §3), `TERM`, учётные данные модели (ниже) и то, что
установят спайки S1–S3 как необходимое харнессу (каждое имя — с
обоснованием). `GH_TOKEN`, `GITHUB_TOKEN`, `GH_CONFIG_DIR` и прочие секреты
сессии оператора в агента не попадают.

**Учётные данные модели.** Claude — из `CLAUDE_CODE_OAUTH_TOKEN` в env
вызова (F8). **Источник:** отдельный элемент связки ключей (например,
`devtools-author-claude-oauth`, значение `claude setup-token`), который
раннер читает ДО обёртки, вне песочницы; унаследованное значение из
окружения оператора не используется — иначе токен на практике уехал бы в
`~/.zshrc`, а с ним в env — всё остальное. Codex — `~/.codex/auth.json`
(чтение разрешено).

**Названный конфликт (принят владельцем для v1).** Свой модельный токен
агенту виден, сеть открыта (нужна для API) — агент может его вывести. Это
риск по деньгам, не по целостности одобрения: GitHub-учётки и артефакты
прогона закрыты, ради них граница и ставится. Сетевой allowlist (только API
модели) — отдельным срезом.

## 4. Проба-канарейка (отрицательная самопроверка)

> **rev 3:** дополнена §15; пункт 5 (запись в `target_dir` обязана удаться)
> заменён — теперь она обязана НЕ удаться, базовая половина — запись в каталог
> вызова.

Перед КАЖДЫМ вызовом агента раннер исполняет под той же обёрткой с тем же
профилем короткий скрипт-пробу:

1. запись канарейки в `run_dir/edge-check/.sandbox-probe` и в
   `$HOME/.sandbox-probe` — обязана **не удаться**;
2. чтение файла-приманки `~/.config/ai-prosto/.sandbox-bait` (раннер кладёт
   его сам) — обязано **не удаться**;
3. связка ключей по ВСЕМ учёткам — каждое обязано **не удаться**:
   `security find-generic-password -s gh:github.com -a ai-prosto`, то же
   с `-a andrei-shtanakov`, общий поиск без `-a`, и элемент
   `Claude Code-credentials` (канарейка по одной записи не видит другую);
4. окружение: множество имён переменных внутри обёртки **равно**
   allowlist'у вызова — ни `GH_TOKEN`/`GITHUB_TOKEN`/`GH_CONFIG_DIR`, ни
   любого другого лишнего имени (равенство множеств, не поиск трёх имён);
5. запись в `target_dir/.sandbox-probe` — обязана **удаться** (базовая
   половина: проба, у которой всё «не удалось», прошла бы и на профиле,
   запрещающем всё).

Любое расхождение — стоп `stopped_author` «песочница не действует: …» с
названным пунктом, **до** платного вызова; следы пробы убираются. Мутации
приёмки: убрать обёртку — проба обязана покраснеть (пункты 1–3); передать
env наследованием — покраснеть (пункт 4); профиль `deny default` без
исключений — покраснеть (пункт 5).

## 5. Позитивная половина — живая приёмка

Песочница, которая запрещает всё, прошла бы пробу 1–3. Поэтому приёмка
v1 — живой прогон авторинга минимум одного узла под обёрткой на каждом
харнессе, который включается (claude; codex и disp — если включаются в v1,
§7): узел написан, гейт узла зелёный, канарейки вне списка нет.

## 6. Вне v1

## 7. Спайки до задач

- **S1 claude**: `claude -p` под профилем §3 с `CLAUDE_CODE_OAUTH_TOKEN` —
  какие пути он реально пишет (`~/.claude.json`, `~/.claude/…`), работает ли
  `--no-session-persistence` без записи в `~/.claude/projects`.
- **S2 codex**: `codex exec --sandbox danger-full-access` под профилем — пути
  записи, работа `auth.json`.
- **S3 disp**: `uv run --project disputatio disp pipeline` под профилем —
  кэш `uv`, сеть к индексу пакетов (или `--frozen --offline`), вложенные
  агенты disputatio.
- **S4**: судьба `sandbox-exec` (F10) — если Apple уберёт, запасной путь.

Решение по составу v1 (только claude или все три) — по итогам S1–S3.
**Правило владельца:** если disp или codex под профилем не работают без
широких дыр — v1 выходит только для claude, профиль не расширяется до
бессмысленности; остальные харнессы — следующим срезом.

## 9. Промежуточная защита до песочницы (решение владельца 2026-09-29)

Находка §8/S1 касается сегодняшнего положения, а не только v1: агент авторинга
без песочницы может записать хук, исполняемый в интерактивных сессиях
оператора или при его следующем коммите. До песочницы действуют две меры —
**обе не граница**:

1. **Изоляция конфигурации claude на вызов** (`ops.claude_isolation`): свой
   временный `CLAUDE_CONFIG_DIR` с `settings.json` (`bypassPermissions`),
   токен — из элемента связки `devtools-author-claude-oauth`, читаемого
   раннером. Закрывает загрузку плагинов/хуков оператора агентом и запись его
   состояния в `~/.claude`. Преднамеренную запись в `~/.claude` по абсолютному
   пути НЕ предотвращает. Нет элемента связки — вызов не делается (код 2).
2. **Трипвайр конфиг-поверхности** — тот же снимок до/после вызова агента, что
   у edge-check (#470). Наблюдается allowlist:
   - `~/.claude/`: `settings.json`, `settings.local.json`, `CLAUDE.md`,
     `keybindings.json`, каталоги `hooks/`, `skills/`, `commands/`, `agents/`;
   - из `~/.claude/plugins/` — только реестр установленного и включённого:
     `installed_plugins.json`, `known_marketplaces.json`, `config.json`,
     `blocklist.json`;
   - из `~/.claude.json` — только поддеревья `mcpServers` (user-scope и по
     проектам): подсаженный MCP-сервер стартует в следующей сессии;
   - скрипты, на которые ссылаются хуки `settings*.json` (первый токен
     команды — абсолютный путь);
   - в репо, где работает агент: `.claude/`, `.mcp.json`, `.git/hooks/`.

   **Не наблюдаются**: `~/.claude/projects/`, `todos/`, `shell-snapshots/`,
   `plugins/{cache,marketplaces,data,synced}/`, остальной `~/.claude.json`,
   история, статистика и прочее состояние — их пишут параллельные
   интерактивные сессии, и ложный стоп на каждом прогоне приучил бы трипвайр
   отключать (ревью #489). Цена: подмена кода УЖЕ установленного плагина в
   `plugins/cache/` не видна — включить новый плагин без правки реестра или
   `settings.json` нельзя, а подмену кода закроет песочница. **Остальные репо воркспейса** (их `.claude/`, `.mcp.json`,
   `.git/hooks/`) — вне наблюдения до песочницы. Правка наблюдаемого файла
   оператором во время вызова даст стоп — названная цена.

   Реакция: статус `stopped_author` пишется первым, вывод вызова — в карантин
   прогона, стоп называет изменённые файлы. Файлы оператора **не
   откатываются автоматически** — решение за оператором до следующей сессии и
   коммита. Цена снимка на реальном `~/.claude` — ~0,55 с (525 записей;
   до сужения `plugins/` было ~2 с и 11 тыс. файлов).

## 11. Что защищаем и какие записи агенту нужны

Авторский агент получает задачу «напиши ровно один файл узла бандла». Гейты,
edge-check, коммит, ревью и мерж делает раннер вне агента; читает агент всё
дерево цели (код, соседние узлы, source-слой).

**Модель противника.** Противник этого дизайна — авторский агент во время
вызова и все его потомки, в том числе пережившие вызов (§12). Содержимое
настоящего бандла и дерева цели, попавшее туда до вызова (мерж PR, правка
человека, прежние вызовы раннера), — **не** противник этого дизайна: агенту
оно не пишется (§12), а его происхождение — дело ревью PR. Чтение раннером
этого содержимого (source, соседние узлы, subject edge-check) настоящий дизайн
не ужесточает — предел §17 п.10.

| Актив | Где | Угроза от агента | Мера (раздел) |
|---|---|---|---|
| Учётки GitHub (ai-prosto, владелец) | связка ключей, `~/.config/{gh,review}` | approve/merge/push от чужого имени | запрет чтения и mach-запрет связки (§3), env без `GH_*` (§3) |
| Акты одобрения и политики | репо `approval-policy` (удалённый), authority-root и харнесс-пути devtools (`merge-pr.sh`, `human-merge.sh`, `governance/`, `contracts/`) | правка политики, гварда или кода, который раннер затем исполнит с полномочиями ai-prosto | дерево цели целиком вне записи (§12) — в том числе когда цель — сам devtools (бандлы в `workstreams/`) |
| Леджеры и артефакты прогона | `run_dir` (`ledger.jsonl`, `edge-check/`, состояние) | подделка PASS, переиспользования, статуса | вне записи; разрешён только свежий каталог вызова (§12) |
| Git-метаданные цели и соседей | `.git` (каталог или файл-ссылка), gitdir/common dir worktree | `core.fsmonitor`/`core.hooksPath`/хук — код, который исполнит следующий `git` раннера или оператора | вне записи; разрешённые корни не пересекаются с gitdir/common dir (§12); запрет компонента `.git` — второй пояс |
| Бандл: узел и соседние, уже одобренные узлы | `target_dir/<bundle_dir>/` | переписать принятый узел; оставить ссылку, по которой раннер прочтёт чужой файл | бандл агенту НЕ пишется: агент пишет в заготовку, файл узла переносит раннер (§15) |
| Конфигурация и автозапуск оператора | `~/.claude`, `~/.codex`, shell rc, `~/Library/LaunchAgents`, crontab | код, исполняемый вне песочницы позже | вне записи; launchd/cron/LaunchServices закрыты (§12, F20–F21) |
| Кэши и окружения, исполняемые раннером | `~/.cache/uv`, venv disputatio и devtools | отравление кода, который раннер запустит | вне записи (§12, §8/S3) |

**Необходимые записи** — только свежий каталог вызова `<calls>/<run_id>/<call>/`,
созданный раннером (§12). Корень `<calls>` — **вне** чекаута devtools:
`$XDG_STATE_HOME/devtools/agent-calls` (по умолчанию
`~/.local/state/devtools/agent-calls`), по образцу `_disp_anchor_dir`
(`governance/runner.py:2407–2432`). Каталог прогона (`run_dir`) остаётся в
`DEVTOOLS_ROOT/out/governance-runs` (`governance/run_state.py:30`) — агенту он
не пишется, и переносить его не нужно.

1. `stage/` — **заготовка**. Промпт называет **два разных пути**:
   `bundle_dir` — координата настоящего бандла относительно `target_dir`, для
   чтения соседей, source-слоя и `git hash-object` (`governance/ops.py:2088–2096`,
   DSL `ops.py:712–740`); `output_path` — **абсолютный** путь
   `<call>/stage/<file>`, единственное место записи. Родительские каталоги
   внутри заготовки агент создаёт сам (F24, F26).
2. `tmp/` — `TMPDIR` и `CLAUDE_CODE_TMPDIR` (F22).
3. `claude-config/` — `CLAUDE_CONFIG_DIR` (§9).
4. Устройства: `/dev/null`, `/dev/fd/*`. Терминалы — нет: агент запускается
   без управляющего терминала (§12, F28).

Всё прочее — запрещено. Рабочий каталог вызова остаётся `target_dir`: читать
агенту нужно дерево цели, писать — нет.

**disp выходит из v1** (по правилу владельца §7 и §10 п.1). Под обёрткой
оказывается весь процесс `disp`, включая его координатор, а координатор
обязан писать в `.git` цели: `reset --hard`/`clean`
(`disputatio/src/disputatio/runtime/steps.py:301–302`), коммит раунда
(`steps.py:517`), запись exclude/index и коммит (`runtime/git.py:464–475`);
раннер это прямо отмечает (`governance/runner.py:2665–2672`). Пропустить его —
значит открыть `.git` всему дереву процессов; это и есть «профиль, расширенный
до бессмысленности». disp возвращается отдельным срезом, где граница стоит
вокруг агентских подпроцессов disputatio, а координатор остаётся доверенным.

## 12. Модель доступа rev 3 (заменяет правила записи §3)

**Разрешённые корни создаёт раннер, и только так.** До вызова, вне песочницы:

1. Корень `<calls>` канонизируется (`realpath`) один раз; дальше каталоги
   `<run_id>/<call>` открываются и создаются только через дескрипторы
   (`O_NOFOLLOW_ANY|O_DIRECTORY`, `mkdir(…, dir_fd=)`, F27) — ссылка в любом
   компоненте даёт отказ; `<call>` — новый уникальный идентификатор, `mkdir`
   существующего — отказ; затем `stage/`, `tmp/`, `claude-config/` — так же. Свежесозданные пустые
   каталоги не содержат заранее существующих ссылок и hardlink по построению
   (F16 закрыт структурно, а не обходом).
2. `realpath` каталога вызова **не пересекается** (ни предок, ни потомок) с
   `target_dir`, с gitdir и common dir цели (`git rev-parse
   --path-format=absolute --git-dir --git-common-dir`), с чекаутом devtools и с
   `run_dir`. Пересечение — отказ. Корень `<calls>` вне чекаута devtools
   (§11) — поэтому проверка проходит и для цели «сам devtools».
3. Профиль генерируется из этих `realpath` (Seatbelt сверяет разрешённый путь;
   `/tmp` → `/private/tmp`).

```
(version 1)
(allow default)
(deny file-write*)
(allow file-write* (subpath <call>/stage) (subpath <call>/tmp)
                   (subpath <call>/claude-config)
                   (literal "/dev/null") (regex #"^/dev/fd/"))
(deny file-write* (regex #"(^|/)\.git(/|$)"))
(deny file-ioctl (regex #"^/dev/tty"))
(deny file-read* ~/.config/review ~/.config/gh ~/.config/ai-prosto ~/.ssh)
(deny mach-lookup (global-name "com.apple.SecurityServer")
                  (global-name "com.apple.securityd.xpc")
                  (global-name "com.apple.security.agent")
                  (global-name-prefix "com.apple.coreservices.")
                  (global-name-prefix "com.apple.lsd."))
```

`file-write*` покрывает создание, запись, `unlink`, переименование (обе
стороны), `chmod`, создание ссылок; запреты после разрешений сильнее (F15, F17,
F18). Запрет компонента `.git` — второй пояс, а не основная защита: агент может
создать в заготовке gitfile с метаданными под другим именем, но раннер из
заготовки ничего, кроме файла узла, не берёт и git в ней не запускает (§15).

**Временные файлы** — только `tmp/` каталога вызова: `TMPDIR` и
`CLAUDE_CODE_TMPDIR` указывают туда. `/private/tmp` и `/private/var/folders`
целиком не открываются (F11); путь трекинга cwd claude не открывается (F22,
F23).

**Кэши** не открываются: авторскому агенту `uv`/`npm`/`pip` не нужны.

**Symlink** (F14): запись через ссылку проверяется по конечному пути — наружу
нельзя. Создать ссылку агент может только внутри каталога вызова; раннер ссылок
оттуда не читает (§15). Ссылки в самом дереве цели агенту не создать.

**Hardlink:** изнутри наружу не создаётся (F15); заранее существующих в
разрешённых корнях нет — они свежие (п.1 выше).

**Терминал** (F28). Агент запускается **в новой сессии** (`setsid`: без
управляющего терминала оператора) со `stdin` из `/dev/null`; stdout/stderr — в
каналы раннера. Подкладка ввода `TIOCSTI` в терминал оператора закрыта дважды:
нет управляющего терминала (по имени — `EACCES`) и `file-ioctl` на `/dev/tty*`
запрещён профилем.

**Дочерние процессы** наследуют профиль, включая отсоединённые (F19) — и
**переживают вызов**. Поэтому раннер (а) запускает агента лидером новой сессии
и группы процессов и после выхода/таймаута шлёт `SIGKILL` группе — это гигиена, не
гарантия: потомок может уйти из группы `setsid`; (б) **гарантия — в
построении**: всё, что потомок способен записать, лежит в каталоге вызова;
раннер читает оттуда один файл ОДИН раз безопасным примитивом (§15), который
устойчив к подмене во время чтения (ссылка в любом компоненте — отказ ядра,
FIFO — без зависания, чтение ограничено `limit + 1` байтами и временем), и
дальше работает только с прочитанными байтами. Подмена до, во время или после
переноса меняет в худшем случае исход переноса (отказ), но не то, что раннер
записывает и проверяет. Продолжающийся потомок сохраняет чтение и сеть
— предел, §17.

Каналы, которыми процесс просит систему запустить код ВНЕ песочницы: launchd и
cron — отказ (F20); LaunchServices (`open`) — закрыт префиксным mach-запретом
(F21). Apple Events под тем же запретом не получают ответа, но **закрытие не
доказано** (зависание ≠ отсутствие доставки) — §17. Других каналов не
проверено — §17.

**Окружение** — allowlist rev 2 (§3, `agent_env()`) плюс `TMPDIR`,
`CLAUDE_CODE_TMPDIR`, `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_OAUTH_TOKEN` (из элемента
связки, §3), `SSL_CERT_FILE`.

**Таймаут вызова обязателен:** зависание под профилем — штатная форма отказа
(F21, §8/S2). Истёк — `SIGKILL` группе, `stopped_author` «таймаут», переноса
нет.

## 13. Отказ запуска и поддерживаемые окружения

Песочница — условие вызова авторского агента, а не режим. Любое из условий
ниже — `stopped_author` с названной причиной **до** платного вызова; флага,
переменной или «режима с предупреждением», запускающих агента без песочницы,
нет.

| Окружение / состояние | Исход |
|---|---|
| macOS, `/usr/bin/sandbox-exec` есть, исполняемый файл харнесса допущен (§14), проверки §12 и проба §15 зелёные | вызов под песочницей |
| ОС не macOS (VPS/Linux — F1: авторинга там нет) | отказ «песочница авторинга поддерживается только на macOS» |
| нет `sandbox-exec` / профиль не применился | отказ с выводом `sandbox-exec` |
| процесс раннера уже в песочнице (F9: `sandbox_apply: Operation not permitted`) | отказ «вложенная песочница» |
| исполняемый файл харнесса не допущен | отказ «не проверен под песочницей» (§14) |
| проверки §12 или проба §15 не прошли | отказ с названным пунктом |
| нет элемента связки с токеном claude | отказ (уже действует, §9) |
| `AUTHOR_BACKEND=disp` | отказ «disp вне v1» (§11) |
| `AUTHOR_HARNESS` ≠ claude (codex и любой другой) | отказ «харнесс `<имя>` не поддерживается песочницей авторинга v1; поддерживается claude» (Q1 ниже) |

**codex и прочие харнессы — решение владельца 2026-10-11 (Q1, вариант (а)).**
В v1 авторинг любым харнессом, кроме claude, — **отказ до запуска агента**:

- проверка стоит на **всех** входах авторинга — `start`, `resume`, повтор шага,
  волновой режим — до создания каталога вызова и до платного вызова;
- **нет** автоматической замены codex на claude и **нет** флага, переменной или
  режима, запускающих харнесс без песочницы §12;
- отказ называет причину и выход: «харнесс `codex` не поддерживается песочницей
  авторинга v1; поддерживается claude (`AUTHOR_HARNESS=claude`)»;
- тест доказывает, что при отказе процесс агента не запускается (подменённый
  исполняемый файл-маркер не вызван) и файлы цели и бандла не меняются
  (снимок до/после);
- ограничение — **только** авторинг под этой песочницей: ревью codex-ом
  (`review-pr.sh`, edge-check) и интерактивная работа им не затрагиваются.

**Следствие для умолчания.** Резолвер харнесса — env > `harness.env` >
**вшитый `codex`** (`governance/ops.py:460–474`). На машине оператора
`harness.env` задаёт `AUTHOR_HARNESS=claude` (сверено 2026-10-11); на машине
без него авторинг в v1 получит отказ §13. Вшитое умолчание этим срезом **не
меняется**: молча подставить claude там, где резолвер выбрал codex, — та самая
автоматическая замена, которую решение запрещает. Оператор задаёт
`AUTHOR_HARNESS=claude` явно; текст отказа это называет.

Поддержка codex — отдельный срез с собственной проверкой изоляции и состояния
харнесса (`~/.codex`, `CODEX_HOME`, §8/S2). Решение §2 «codex под обёрткой с
`danger-full-access`» отменено этим решением.

## 14. Версия харнесса — допуск исполняемого файла

Разрешения §12 подобраны под конкретное поведение харнесса, и оно дрейфует
(F23; без пути трекинга Bash неработоспособен, F22). Поэтому допускается не
«версия», а конкретный исполняемый файл:

- запись допуска: `(харнесс, версия, realpath исполняемого файла, sha256 его
  содержимого, мажорная версия macOS, sha256 шаблона профиля §12)`; файл
  `contracts/author-sandbox/v1/admitted.toml`;
- **регистрация в authority-root** — часть того же среза: префикс
  `contracts/author-sandbox/` вносится в
  `contracts/authority-root/v1/paths.env` (сейчас его там нет), с тестом, что
  агентский PR, трогающий допуск, `merge-pr.sh` отказывает;
- раннер ДО вызова, вне песочницы, **ничего не исполняя**: резолвит харнесс в
  `PATH` раннера (`shutil.which` → `realpath`), читает файл безопасным
  примитивом (§15) и считает sha256, читает `sw_vers -productVersion` (системный
  бинарь, не кандидат); пары `(realpath, sha256)` с той же ОС и шаблоном
  профиля нет в контракте — отказ (§13). Версия берётся **из записи допуска**:
  неизвестный исполняемый файл до отказа не запускается ни с каким аргументом,
  включая `--version`;
- запускается **именно этот абсолютный путь**, а не имя из `PATH`;
- **допуск новой версии** — процедура (новая цель `make sandbox-admit`,
  исполняет оператор): проба харнесса под профилем §12 — коды Bash 0/1/3,
  сохранение `cd`, Write в заготовку с родительскими каталогами, отказ записи в
  дерево цели, ничего не записано вне каталога вызова (снимки
  `$HOME`-поверхности и `/private/tmp` до/после), проба §15 зелёная; протокол —
  в `docs/evidence/`, запись допуска — тем же PR (мержит человек). Проба не
  прошла — версия не допускается; расширение профиля — изменение этого
  дизайна, не строка контракта.

## 15. Проба, перенос результата, проверки (дополняет §4)

**Проба-канарейка** — перед каждым вызовом, под той же обёрткой и профилем, с
таймаутом. Пункты §4 1–4 сохраняются; **пункт 5 §4 заменён**: запись в
`target_dir` теперь обязана НЕ удаться. Обязаны **не удаться** также:

- в настоящей цели — **только неразрушающие** пробы: создание нового
  уникального файла-часового (`O_CREAT|O_EXCL`, имя с UUID) в `target_dir`, в
  `target_dir/<bundle_dir>/`, в gitdir и в common dir цели. Каталоги бандла
  раннер **до пробы** создаёт сам безопасной записью (§15) — первый запуск без
  бандла и без его родителей штатен. Засчитывается только `EPERM`; `ENOENT`,
  `EEXIST` и прочие ошибки — сбой подготовки, отказ вызова, а не «защита
  работает». Удалось — регрессия профиля: часовой удаляется, вызов не делается;
  существующие файлы и метаданные проба не трогает;
- без управляющего терминала: открытие `/dev/tty` обязано не удаться (F28);
- **разрушающие** пробы (`unlink`, переименование и подмена файла `.git`
  worktree, запись в `config`/`hooks`) — на одноразовом стенде git-репо +
  worktree, который раннер создаёт для пробы вне разрешённых корней и удаляет
  после;
- `ln <файл вне> <call>/stage/x`;
- `launchctl submit` пробного задания, пишущего файл снаружи, — обязан вернуть
  ненулевой код, а после пробы метки задания нет в `launchctl list`;
- `open -g` пробного `.app` из каталога вызова, пишущего файл снаружи (F21), —
  ненулевой код, `lsappinfo front` → NULL.

Любой результат, кроме явного отказа (код 0, таймаут, неоднозначность), —
отказ запуска, а не «прошло»; пробные задания и файлы убираются в `finally`.
Отсутствие файла-эффекта — дополнительное условие, не основное (задание может
исполниться позже).

Обязаны **удаться** (базовая половина): запись в `<call>/stage/` и `<call>/tmp/`.

**Безопасный ввод-вывод раннера** (F27) — единственный способ, которым раннер
касается заготовки и пишет файл узла в бандл:

- корни (`<calls>`, `target_dir`) канонизируются `realpath` один раз; каждое
  открытие — `O_NOFOLLOW_ANY` (ссылка в любом компоненте — отказ ядра, без
  гонки «проверил компонент → подменили»);
- чтение: `O_RDONLY|O_NONBLOCK|O_NOFOLLOW_ANY`, затем `fstat` открытого
  дескриптора — только обычный файл с `st_nlink == 1`; чтение не более
  `limit + 1` байт с ограничением времени (больше `limit` — отказ);
- запись: родительские каталоги назначения открываются и при необходимости
  создаются через цепочку дескрипторов (`O_DIRECTORY|O_NOFOLLOW_ANY`,
  `mkdir(…, dir_fd=)`); байты пишутся во временный файл
  `O_CREAT|O_EXCL|O_NOFOLLOW` в закреплённом каталоге и публикуются
  `rename(…, src_dir_fd, dst_dir_fd)` поверх конечного имени. Висячая ссылка
  на месте узла заменяется самой ссылкой, её цель не создаётся; hardlink
  получает новый inode, внешний двойник не меняется (F27); конечное имя —
  каталог — отказ.

**Контракт назначения.** `bundle_dir` — непустой относительный путь без `..`,
без абсолютных и пустых компонентов, не `.`, без компонента `.git`; после
канонизации — строго внутри `target_dir` и не пересекается с gitdir/common dir
цели. Иначе — отказ до вызова агента.

**Перенос результата** — один раз, после выхода агента (не после таймаута):

1. Файл `<call>/stage/<file>` читается безопасным примитивом; в заготовке нет
   ничего, кроме него (перечень — через тот же примитив, без следования
   ссылкам); иначе — `stopped_author` с перечнем (в карантин прогона, как §9).
2. Прочитанные байты публикуются в `target_dir/<bundle_dir>/<file>` безопасной
   записью. Гейт, edge-check, штамп и коммит потребляют файл, записанный
   раннером; в заготовку раннер больше не смотрит; каталог вызова удаляется.
3. Отказ на любом шаге — вне дерева цели ничего не создано и не изменено
   (внешние файлы побайтно те же), и это проверяется тестом даже при
   последующем отказе гейта.

## 17. Пределы гарантий — чего песочница НЕ ограничивает

**Это песочница с ограниченными гарантиями, не полная изоляция агента.**

1. **Чтение прочих секретов.** Закрыты только `~/.config/{review,gh,ai-prosto}`,
   `~/.ssh` и связка ключей. Всё остальное читается: `~/.aws`, `~/.netrc`,
   `~/.docker/config.json`, `~/.codex/auth.json`, `.env` и секреты в других
   репо воркспейса, история оболочки, профили браузеров, исходники всех репо.
   Переменные из allowlist (§3) агенту видны, включая облачные ключи модели,
   если они выставлены.
2. **Сеть открыта.** Прочитанное можно отправить куда угодно; можно скачать и
   исполнить код — внутри песочницы, с её запретами записи.
3. **GitHub API.** Токены ai-prosto и владельца закрыты, но любой токен,
   найденный в читаемых файлах (п.1), работает; анонимный API — тоже.
   Публикация от найденной учётки песочницей не предотвращается.
4. **Модельный токен агента** виден ему (§3, принято для v1) — риск по деньгам.
5. **Содержимое узла.** Агент пишет в файл узла что угодно; правильность —
   работа гейта, edge-check и ревью, не песочницы.
6. **Потомки переживают вызов.** Отсоединённый процесс агента может
   продолжать читать и ходить в сеть после возврата (п.1–3) и до перезагрузки;
   записать он может только в мёртвый каталог вызова. Ресурсы (CPU, память,
   диск каталога вызова) ограничены только таймаутом основного процесса.
7. **Apple Events и прочие каналы выхода.** Закрыты проверенные (launchd, cron,
   LaunchServices, подкладка ввода в терминал — F20, F21, F28). Apple Events под префиксным запретом не получают
   ответа, но доставка события не исключена доказательно. Прочие XPC-сервисы,
   способные исполнить код вне песочницы, не перечислены: `(allow default)` —
   осознанный выбор rev 2 (§3), `deny default` требует полного перечня,
   которого нет.
8. **`sandbox-exec` устарел** (F10). Регрессию запретов ловит проба на каждом
   вызове, избыточный запрет — базовая половина и допуск (§14); исчезновение
   бинаря — отказ запуска (§13).
9. **Агенты вне обёртки** — disp (§11), discovery, ревьюер edge-check,
   исполнители spec-runner (spec-runner#600), `ops.review`. Авторинг codex в v1
   невозможен (отказ, Q1 §13) — его ревью и интерактивная работа этим дизайном
   не ограничиваются.
10. **Чтение раннером прежнего содержимого бандла.** Source-слой, соседние
    узлы, subject edge-check, штамп — раннер читает их обычным путём (в т.ч.
    `edge_check/coordinator.py:281–289, 355–358` следует по ссылкам до проверки
    копии). Агенту эти файлы не пишутся (§12), поэтому противник этого дизайна
    их не формирует (§11, модель противника); но ссылка или FIFO, попавшие туда
    через смёрженный PR, раннером не отсеиваются. Перевод этих чтений на
    безопасный примитив §15 — отдельный пункт ужесточения, не v1.
