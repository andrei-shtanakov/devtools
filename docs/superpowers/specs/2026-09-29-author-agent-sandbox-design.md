# Песочница авторского агента — дизайн (devtools#469 п.2)

**Статус:** дизайн, **rev 3, 2026-10-11 — на ревью**. Rev 2 (2026-09-29) одобрен
владельцем; rev 3 вносит требования владельца 2026-10-11 и пробы осуществимости
того же дня (§11–§18, F14–F25). Номера §1–§10 сохранены — на них ссылаются код
и tasks-спека; разделы, которые rev 3 заменяет, помечены на месте. Tasks-спека
(`spec/author-agent-sandbox-tasks.md`) пересматривается после одобрения rev 3.
TODO: `author-agent-sandbox`.

**Цель.** Настоящая граница записи и чтения для агентов, которых запускает
раннер на стадии авторинга. Сегодня её нет: `claude --dangerously-skip-permissions`
пишет и читает что угодно по абсолютному пути, и вся локальная защита
edge-check упирается в потолок «двух согласованных артефактов»
(devtools#469, #478). Трипвайр #470 остаётся — он ловит запись в своё окно,
песочница её предотвращает.

**Это песочница с ограниченными гарантиями, не полная изоляция агента.** Она
закрывает запись вне каталога узла, чтение учётных данных GitHub и проверенные
каналы выхода из неё (launchd, cron, LaunchServices). Она **не** закрывает
чтение прочих секретов, сеть, GitHub API через найденный агентом токен и
содержимое самого узла — полный перечень с последствиями в §17, и никакой
текст, ссылающийся на песочницу, не вправе обещать больше.

## 2. Нативная песочница харнесса или внешняя обёртка

| | Нативная (Claude Code sandbox, codex `--sandbox`) | Внешняя (`sandbox-exec` вокруг процесса) |
|---|---|---|
| Что ограничено | Claude: только Bash-команды; **файловые инструменты (Read/Write/Edit) — нет**. Codex: запись рабочим каталогом, чтение — не ограничено | весь процесс и все потомки, все инструменты |
| Где задаётся | Claude: `.claude/settings.json` в проекте — **агент может его править**; codex: флаг | профиль у раннера, вне дерева цели |
| Связка ключей | Claude: документация молчит; codex: не установлено | запрещается `mach-lookup` (F6) |
| Кода у нас | меньше | профиль + обёртка + проба |
| Риск | доверие харнессу, у каждого своя модель | F10 (DEPRECATED) |

**Решение: внешняя обёртка.** Нативная у claude не закрывает главного —
файловые инструменты и чтение токенов, а конфиг достижим агенту. Следствие
F9: у codex собственный `--sandbox workspace-write` внутри обёртки не
запустится — под обёрткой codex идёт с `--sandbox danger-full-access`,
ограничение целиком снаружи (одна модель для обоих харнессов). **Это
ослабление, а не перенос один в один:** `workspace-write` закрывает codex
сеть (F13), а под обёрткой сеть открыта (§3). Для claude сеть открыта и
сегодня; для codex v1 сеть открывает — названо и принято вместе с §3.

**Отказ обёртки — стоп, не предупреждение.** Нет бинаря `sandbox-exec`,
профиль не применился, проба (§4) не прошла — раннер не запускает агента
вовсе (`stopped_author` с причиной). Запуска «без обёртки, с
предупреждением» не существует: это вернуло бы ровно сегодняшнее
состояние под видом защищённого.

## 3. Модель доступа (профиль Seatbelt)

> **rev 3:** правила записи этого раздела заменены §12 — запись сужена с
> `target_dir` до каталога бандла узла, путь трекинга cwd не открывается
> (`CLAUDE_CODE_TMPDIR`), добавлен mach-запрет LaunchServices. Чтение, env и
> учётные данные модели — без изменений.

База — `(allow default)` с запретами (как в замере), а не `(deny default)`:
пустой разрешающий список для node/codex/uv неизвестен до спайков (§7), и
`deny default` дал бы песочницу, запрещающую работу. Граница задаётся
запретами:

**Запись** — запрещена всюду, кроме:
- `target_dir` (дерево цели — туда автор пишет узел; `.git` внутри);
- у disp — каталог анкера P9 прогона (`run_dir/disp-anchors` либо
  XDG-state, `_pinned_disp_anchor_dir`);
- **свой временный каталог вызова** (`TMPDIR` = `run_dir/agent-tmp/<call>`);
  `/private/tmp` и `/private/var/folders` целиком НЕ разрешаются (F11);
- собственное состояние харнесса — перечень устанавливает спайк S1/S2
  (`~/.claude*`, `~/.codex/sessions`, кэш `uv` для disp); каждый путь — с
  обоснованием в профиле.

`run_dir/edge-check/` и остальной каталог прогона агенту **не пишутся**.

**Чтение** — запрещено: `~/.config/review`, `~/.config/gh`,
`~/.config/ai-prosto`, `~/.ssh`. **Связка ключей** — запрет `mach-lookup`
к трём сервисам (F6).

**Окружение — allowlist, не наследование** (F12). Раннер собирает env
вызова с нуля из закрытого перечня: `PATH`, `HOME`, `USER`, `LANG`/`LC_*`,
`TMPDIR` (свой, §3), `TERM`, учётные данные модели (ниже) и то, что
установят спайки S1–S3 как необходимое харнессу (каждое имя — с
обоснованием). `GH_TOKEN`, `GITHUB_TOKEN`, `GH_CONFIG_DIR` и прочие секреты
сессии оператора в агента не попадают.

**Учётные данные модели.** Claude — из `CLAUDE_CODE_OAUTH_TOKEN` в env
вызова (F8). **Источник:** отдельный элемент связки ключей (например,
`devtools-author-claude-oauth`, значение `claude setup-token`), который
раннер читает ДО обёртки, вне песочницы; унаследованное значение из
окружения оператора не используется — иначе токен на практике уехал бы в
`~/.zshrc`, а с ним в env — всё остальное. Codex — `~/.codex/auth.json`
(чтение разрешено).

**Названный конфликт (принят владельцем для v1).** Свой модельный токен
агенту виден, сеть открыта (нужна для API) — агент может его вывести. Это
риск по деньгам, не по целостности одобрения: GitHub-учётки и артефакты
прогона закрыты, ради них граница и ставится. Сетевой allowlist (только API
модели) — отдельным срезом.

## 4. Проба-канарейка (отрицательная самопроверка)

> **rev 3:** дополнена §15 (проверки до и после вызова, новые пункты пробы).

Перед КАЖДЫМ вызовом агента раннер исполняет под той же обёрткой с тем же
профилем короткий скрипт-пробу:

1. запись канарейки в `run_dir/edge-check/.sandbox-probe` и в
   `$HOME/.sandbox-probe` — обязана **не удаться**;
2. чтение файла-приманки `~/.config/ai-prosto/.sandbox-bait` (раннер кладёт
   его сам) — обязано **не удаться**;
3. связка ключей по ВСЕМ учёткам — каждое обязано **не удаться**:
   `security find-generic-password -s gh:github.com -a ai-prosto`, то же
   с `-a andrei-shtanakov`, общий поиск без `-a`, и элемент
   `Claude Code-credentials` (канарейка по одной записи не видит другую);
4. окружение: множество имён переменных внутри обёртки **равно**
   allowlist'у вызова — ни `GH_TOKEN`/`GITHUB_TOKEN`/`GH_CONFIG_DIR`, ни
   любого другого лишнего имени (равенство множеств, не поиск трёх имён);
5. запись в `target_dir/.sandbox-probe` — обязана **удаться** (базовая
   половина: проба, у которой всё «не удалось», прошла бы и на профиле,
   запрещающем всё).

Любое расхождение — стоп `stopped_author` «песочница не действует: …» с
названным пунктом, **до** платного вызова; следы пробы убираются. Мутации
приёмки: убрать обёртку — проба обязана покраснеть (пункты 1–3); передать
env наследованием — покраснеть (пункт 4); профиль `deny default` без
исключений — покраснеть (пункт 5).

## 5. Позитивная половина — живая приёмка

Песочница, которая запрещает всё, прошла бы пробу 1–3. Поэтому приёмка
v1 — живой прогон авторинга минимум одного узла под обёрткой на каждом
харнессе, который включается (claude; codex и disp — если включаются в v1,
§7): узел написан, гейт узла зелёный, канарейки вне списка нет.

## 6. Вне v1

## 7. Спайки до задач

- **S1 claude**: `claude -p` под профилем §3 с `CLAUDE_CODE_OAUTH_TOKEN` —
  какие пути он реально пишет (`~/.claude.json`, `~/.claude/…`), работает ли

бессмысленности; остальные харнессы — следующим срезом.

## 8. Результаты спайков (2026-09-29)

Все прогоны — с env из `agent_env()` (#483), не унаследованным; профиль —
§3; токен claude читается раннером из элемента связки
`devtools-author-claude-oauth` ВНЕ обёртки и передаётся только в env вызова.

### S1 claude — пройден

| | Минимальный набор |
|---|---|
| Запись | `target_dir`; свой `TMPDIR`; `/private/tmp/claude-<uid>/<slug(cwd)>*` — трекинг cwd Bash-инструмента, путь зашит, от `TMPDIR` не зависит (разрешается регэкспом по префиксу slug дерева узла, не весь `/private/tmp/claude-<uid>`) |
| Чтение (запрещено) | `~/.config/{review,gh,ai-prosto}`, `~/.ssh`, связка ключей |
| env | `agent_env()` + `TMPDIR` + `CLAUDE_CODE_OAUTH_TOKEN` + **`CLAUDE_CONFIG_DIR`** = свой каталог вызова |
| Сверх дизайна | путь трекинга cwd; изоляция конфигурации (`CLAUDE_CONFIG_DIR`) — ужесточение |

> **rev 3:** путь трекинга cwd из таблицы выше устарел (F23): claude 2.1.296
> пишет в `CLAUDE_CODE_TMPDIR`, и разрешение на `/private/tmp/claude-<uid>/…`
> больше не нужно (§12).

**Находка S1.** Без `CLAUDE_CONFIG_DIR` Bash-инструмент пишет в
`~/.claude/` (`shell-snapshots`, `sessions`, `session-env` со скриптом
SessionStart-хука, `security`, `plugins/cache`) — и агент загружает плагины
и хуки оператора. Открыть `~/.claude` на запись — самая широкая дыра: агент
подложил бы хуки/настройки, исполняемые в сессиях оператора. С
`CLAUDE_CONFIG_DIR` в своём каталоге `~/.claude` не тронут (замер), Bash
работает (реальный вывод `ls -la`). Write-инструмент работает и без Bash-путей.

### S2 codex — пройден

| | Минимальный набор |
|---|---|
| Запись | `target_dir`; свой `TMPDIR`; `~/.codex/` |
| env | `agent_env()` + `TMPDIR` + **`SSL_CERT_FILE=/etc/ssl/cert.pem`** |
| Сверх дизайна | `~/.codex/`; `SSL_CERT_FILE` |

**Конфликт найден и снят.** Связку ключей закрывает только запрет
`com.apple.SecurityServer` (`securityd.xpc` и `security.agent` поодиночке —
утечка всех пяти проб), и он же ломает TLS codex (`workspace routing
discovery failed`). `SSL_CERT_FILE` возвращает codex сеть при закрытой связке.
Под неполным профилем codex **зависает**, а не падает — вызову нужен таймаут.

**Открыто для v1.** `~/.codex/` на запись несёт `config.toml` и `AGENTS.md` —
тот же класс, что `~/.claude`: агент поменял бы конфиг и инструкции
интерактивного codex оператора. Кандидат — `CODEX_HOME` на свой каталог с
копией `auth.json` (копия учётки на диске прогона — отдельное решение). До

## 9. Промежуточная защита до песочницы (решение владельца 2026-09-29)

Находка §8/S1 касается сегодняшнего положения, а не только v1: агент авторинга
без песочницы может записать хук, исполняемый в интерактивных сессиях
оператора или при его следующем коммите. До песочницы действуют две меры —
**обе не граница**:

1. **Изоляция конфигурации claude на вызов** (`ops.claude_isolation`): свой
   временный `CLAUDE_CONFIG_DIR` с `settings.json` (`bypassPermissions`),
   токен — из элемента связки `devtools-author-claude-oauth`, читаемого
   раннером. Закрывает загрузку плагинов/хуков оператора агентом и запись его
   состояния в `~/.claude`. Преднамеренную запись в `~/.claude` по абсолютному
   пути НЕ предотвращает. Нет элемента связки — вызов не делается (код 2).
2. **Трипвайр конфиг-поверхности** — тот же снимок до/после вызова агента, что
   у edge-check (#470). Наблюдается allowlist:
   - `~/.claude/`: `settings.json`, `settings.local.json`, `CLAUDE.md`,
     `keybindings.json`, каталоги `hooks/`, `skills/`, `commands/`, `agents/`;
   - из `~/.claude/plugins/` — только реестр установленного и включённого:
     `installed_plugins.json`, `known_marketplaces.json`, `config.json`,
     `blocklist.json`;
   - из `~/.claude.json` — только поддеревья `mcpServers` (user-scope и по
     проектам): подсаженный MCP-сервер стартует в следующей сессии;
   - скрипты, на которые ссылаются хуки `settings*.json` (первый токен
     команды — абсолютный путь);
   - в репо, где работает агент: `.claude/`, `.mcp.json`, `.git/hooks/`.

   **Не наблюдаются**: `~/.claude/projects/`, `todos/`, `shell-snapshots/`,
   `plugins/{cache,marketplaces,data,synced}/`, остальной `~/.claude.json`,
   история, статистика и прочее состояние — их пишут параллельные
   интерактивные сессии, и ложный стоп на каждом прогоне приучил бы трипвайр
   отключать (ревью #489). Цена: подмена кода УЖЕ установленного плагина в
   `plugins/cache/` не видна — включить новый плагин без правки реестра или
   `settings.json` нельзя, а подмену кода закроет песочница. **Остальные репо воркспейса** (их `.claude/`, `.mcp.json`,
   `.git/hooks/`) — вне наблюдения до песочницы. Правка наблюдаемого файла
   оператором во время вызова даст стоп — названная цена.

   Реакция: статус `stopped_author` пишется первым, вывод вызова — в карантин
   прогона, стоп называет изменённые файлы. Файлы оператора **не
   откатываются автоматически** — решение за оператором до следующей сессии и
   коммита. Цена снимка на реальном `~/.claude` — ~0,55 с (525 записей;
   до сужения `plugins/` было ~2 с и 11 тыс. файлов).

5. *rev 3: закрыто сужением записи до каталога бандла (§12) — всё дерево цели вне бандла, включая `.git` целиком, запрещено.* **Запрет записи в `.git/hooks/` и `.claude/` ВСЕХ репо воркспейса** (и
   `~/.claude` целиком, кроме собственного каталога конфигурации вызова) —
   закрывает то, что трипвайр §9 лишь наблюдает, и то, что он не видит.

codex (`CODEX_HOME` с копией `auth.json`) — отдельный issue: копия создаётся
на время вызова вне досягаемости агента после вызова и удаляется в `finally`.

## 11. Что защищаем и какие записи агенту нужны

Авторский агент получает задачу «напиши ровно один файл узла бандла»
(`ops.author`, промпт `Write EXACTLY one file: <bundle_dir>/<file>`); коммит,
гейты, ревью и мерж делает раннер вне агента.

| Актив | Где | Угроза от агента | Мера (раздел) |
|---|---|---|---|
| Учётки GitHub (ai-prosto, владелец) | связка ключей, `~/.config/{gh,review}` | approve/merge/push от чужого имени | запрет чтения и mach-запрет связки (§3), env без `GH_*` (§3) |
| Акты одобрения и политики | репо `approval-policy` (удалённый), authority-root и харнесс-пути devtools (`merge-pr.sh`, `human-merge.sh`, `governance/`, `contracts/`) | правка политики, гварда или кода, который раннер затем исполнит с полномочиями ai-prosto | запись только в каталог бандла (§12): когда цель — сам devtools (бандлы в `workstreams/`), его код и контракты вне разрешённого |
| Леджеры и артефакты прогона | `run_dir` (`ledger.jsonl`, `edge-check/`, состояние) | подделка PASS, переиспользования, статуса | вне разрешённой записи (§12) |
| Git-метаданные цели и соседей | `.git` (каталог или файл-ссылка), gitdir/common dir worktree, `.git/hooks`, `.git/config` | `core.fsmonitor`/`core.hooksPath`/хук — код, который исполнит следующий `git` раннера или оператора вне песочницы | вне разрешённой записи + явный запрет любого компонента `.git` внутри разрешённого (§12, F18) |
| Прочие файлы дерева цели вне бандла | код и конфиги цели, `.claude/`, `.mcp.json` | правка кода/конфигов мимо узла | вне разрешённой записи (§12) |
| Уже одобренные узлы того же бандла | соседние файлы в `bundle_dir` | переписать принятый узел | проверка после вызова: изменился только файл узла (§15) |
| Конфигурация и автозапуск оператора | `~/.claude`, `~/.codex`, shell rc, `~/Library/LaunchAgents`, crontab | хук/агент, исполняемый вне песочницы позже | вне разрешённой записи; launchd/cron/LaunchServices закрыты (§12, F20–F21) |
| Кэши и окружения, исполняемые раннером | `~/.cache/uv`, venv disputatio и devtools | отравление кода, который раннер запустит | вне разрешённой записи (§12, §8/S3) |

**Необходимые записи** (и только они):

1. **Каталог бандла узла** `target_dir/<bundle_dir>/` — файл узла и его
   родительские каталоги (F24).
2. **Каталог вызова** `run_dir/agent-tmp/<call>/` — его `tmp/` служит
   `TMPDIR` и `CLAUDE_CODE_TMPDIR` (F22), `claude-config/` —
   `CLAUDE_CONFIG_DIR` (§9). Создаётся раннером до вызова, удаляется после.
3. **Только disp** (условно в v1, §10 п.1): `target_dir/.disputatio/` и каталог
   анкера P9 (§8/S3).
4. Устройства: `/dev/null`, `/dev/tty`, `/dev/ttys*`, `/dev/fd/*`.

Всё прочее — запрещено. Сужение с `target_dir` (rev 2) до каталога бандла
закрывает разом `.git`, код цели и — что rev 2 упускал — код и контракты самого
devtools, когда бандл пишется в devtools.

## 12. Модель доступа rev 3 (заменяет правила записи §3)

Профиль генерируется раннером по координатам вызова; все пути — **после
`realpath`** (Seatbelt сверяет разрешённый путь; `/tmp` → `/private/tmp`).
Несовпадение даст отказ в штатной записи — его ловит базовая половина пробы.

```
(version 1)
(allow default)
(deny file-write*)
(allow file-write* (subpath <bundle>) (subpath <call>/tmp) (subpath <call>/claude-config)
                   [disp: (subpath <target>/.disputatio) (subpath <p9-anchor>)]
                   (literal "/dev/null") (literal "/dev/tty")
                   (regex #"^/dev/ttys[0-9]+$") (regex #"^/dev/fd/"))
(deny file-write* (regex #"(^|/)\.git(/|$)") (regex #"(^|/)\.claude(/|$)")
                  (regex #"/\.mcp\.json$"))
(deny file-read* ~/.config/review ~/.config/gh ~/.config/ai-prosto ~/.ssh)
(deny mach-lookup (global-name "com.apple.SecurityServer")
                  (global-name "com.apple.securityd.xpc")
                  (global-name "com.apple.security.agent")
                  (global-name-prefix "com.apple.coreservices.")
                  (global-name-prefix "com.apple.lsd."))
```

`file-write*` покрывает создание, запись, `unlink`, переименование (обе стороны),
`chmod`, создание ссылок; запреты после разрешений сильнее (F15, F17, F18).

**Рабочий каталог** вызова остаётся `target_dir` — агент читает дерево цели,
`git status/log/diff` работают при запрещённом `.git` (F24).

**Временные файлы** — только `<call>/tmp`: `TMPDIR` и `CLAUDE_CODE_TMPDIR`
указывают туда. `/private/tmp` и `/private/var/folders` целиком не
открываются (F11); путь трекинга cwd claude не открывается (F22, F23).

**Кэши** — не открываются: `uv`/`npm`/`pip` под песочницей их не получат;
авторскому агенту они не нужны, disp запускается бинарём venv (§8/S3).

**Symlink** (F14): запись через ссылку проверяется по конечному пути —
наружу нельзя. Создание ссылки внутри разрешённого разрешено, поэтому
последствие ловит проверка после вызова (§15): раннер вне песочницы читает
файлы бандла (гейт, edge-check, коммит), и ссылка `node.md → ~/.aws/credentials`
унесла бы содержимое в PR или к ревьюеру.

**Hardlink:** изнутри наружу не создаётся (F15); **существовавший до вызова —
дыра** (F16), её закрывает проверка до вызова (§15).

**Дочерние процессы** наследуют профиль, включая отсоединённые (F19). Каналы,
которыми процесс просит систему запустить код ВНЕ песочницы: launchd и cron —
отказ (F20); LaunchServices (`open`) и Apple Events — закрыты префиксным
mach-запретом (F21). Других каналов в v1 не проверено — это предел (§17).

**Окружение** — allowlist rev 2 (§3, `agent_env()`) плюс `TMPDIR`,
`CLAUDE_CODE_TMPDIR`, `CLAUDE_CONFIG_DIR`, `CLAUDE_CODE_OAUTH_TOKEN` (из элемента
связки, §3), `SSL_CERT_FILE`.

**Таймаут вызова обязателен:** под профилем зависание — штатная форма отказа
(F21 Apple Events, §8/S2 codex). Истёк — `stopped_author` «таймаут».

## 13. Отказ запуска и поддерживаемые окружения

Песочница — условие вызова авторского агента, а не режим. Любое из условий
ниже — `stopped_author` с названной причиной **до** платного вызова; флага,
переменной или «режима с предупреждением», запускающих агента без песочницы,
нет и не будет.

| Окружение / состояние | Исход |
|---|---|
| macOS, `/usr/bin/sandbox-exec` есть, пара (версия харнесса, мажорная версия macOS) допущена (§14), проба зелёная | вызов под песочницей |
| ОС не macOS (VPS/Linux — F1: авторинга там нет) | отказ «песочница авторинга поддерживается только на macOS» |
| нет `sandbox-exec` / профиль не применился | отказ с выводом `sandbox-exec` |
| процесс раннера уже в песочнице (F9: `sandbox_apply: Operation not permitted`) | отказ «вложенная песочница» |
| пара (харнесс, macOS) не допущена | отказ «версия не проверена под песочницей» (§14) |
| проверка до вызова или проба не прошли (§15) | отказ с названным пунктом |
| нет элемента связки с токеном claude | отказ (уже действует, §9) |

**codex и прочие харнессы вне v1 — открытый вопрос владельцу (Q1).** Сегодня
codex авторит под собственной `--sandbox workspace-write` (запись в
`target_dir`, сеть закрыта; чтение и связка ключей не ограничены). Варианты
после включения песочницы:
(а) **отказ запуска** авторинга любым харнессом без песочницы §12 до его
собственного среза — один режим, одна граница;
(б) codex остаётся на нативной песочнице, и граница называется в выводе и
леджере прогона («нативная codex workspace-write, не §12») — не молчаливый
переход, но второй, более слабый режим.
Рекомендация — (а): требование «без незаметного перехода в неограниченный
режим» (б) формально выполняет, но держит два режима с разными гарантиями под
одним словом «песочница». До решения tasks-спека не пишется.

## 15. Проверки до и после вызова; проба rev 3 (дополняет §4)

**До вызова** (раннер, вне песочницы):

3. Снимок разрешённых каталогов (путь, тип, размер, mtime, хэш) — для проверки
   после.

**Проба-канарейка** — пункты §4 плюс (каждый обязан **не удаться**, кроме
последнего):

- запись в `target_dir` вне бандла; запись в `target_dir/.git/config`;
  `unlink`/переименование `.git` в worktree-цели (если цель — worktree); запись

Проба исполняется с таймаутом; её следы убираются.

**После вызова** (раннер, вне песочницы):

1. В бандле изменился только файл узла (у disp — ещё `.disputatio/`); иначе —
   `stopped_author` с перечнем, вывод — в карантин прогона (как §9).
2. Файл узла — обычный файл, `st_nlink == 1`; в разрешённых каталогах нет
   новых symlink (F14). Иначе — тот же стоп, файлы по ссылкам раннер не читает.
3. Каталог вызова удаляется.

## 17. Пределы гарантий — чего песочница НЕ ограничивает

**Это песочница с ограниченными гарантиями, не полная изоляция агента.**

1. **Чтение прочих секретов.** Закрыты только `~/.config/{review,gh,ai-prosto}`,
   `~/.ssh` и связка ключей. Всё остальное читается: `~/.aws`, `~/.netrc`,
   `~/.docker/config.json`, `~/.codex/auth.json`, `.env` и секреты в других
   репо воркспейса, история оболочки, профили браузеров, исходники всех репо.
   Переменные из allowlist (§3) агенту видны, включая облачные ключи модели,
   если они выставлены.
2. **Сеть открыта.** Прочитанное можно отправить куда угодно; можно скачать и
   исполнить код — внутри песочницы, с её запретами записи.
3. **GitHub API.** Токены ai-prosto и владельца закрыты, но любой токен,
   найденный в читаемых файлах (п.1), работает; анонимный API — тоже. Публикация
   от найденной учётки песочницей не предотвращается.
4. **Модельный токен агента** виден ему (§3, принято для v1) — риск по деньгам.
5. **Содержимое узла.** Внутри бандла агент пишет что угодно; правильность —
   работа гейта, edge-check и ревью, не песочницы.
6. **Ресурсы** — CPU, память, диск в разрешённых каталогах; ограничен только
   временем (таймаут).
7. **Гонки с процессами оператора.** Проверка до вызова (hardlink, снимок) не
   видит изменений, сделанных другими процессами во время вызова.
8. **Непроверенные каналы выхода.** Закрыты проверенные (launchd, cron,
   LaunchServices, Apple Events — F20, F21); прочие XPC-сервисы, способные
   исполнить код вне песочницы, не перечислены. `(allow default)` — осознанный
   выбор rev 2 (§3): `deny default` требует полного перечня, которого нет.
9. **`sandbox-exec` устарел** (F10). Регрессию запретов ловит проба на каждом
   вызове, избыточный запрет — базовая половина и допуск версии (§14); исчезновение
   бинаря — отказ запуска (§13).
10. **Агенты вне обёртки** — discovery, ревьюер edge-check, исполнители
    spec-runner (spec-runner#600), `ops.review`: не авторский вызов, §6.
