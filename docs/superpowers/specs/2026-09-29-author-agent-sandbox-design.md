# Песочница авторского агента — дизайн (devtools#469 п.2)

**Статус:** черновик дизайна, rev 1, 2026-09-29. Задачи (tasks-спека) — после
одобрения владельцем. TODO: `author-agent-sandbox`.

**Цель.** Настоящая граница записи и чтения для агентов, которых запускает
раннер на стадии авторинга. Сегодня её нет: `claude --dangerously-skip-permissions`
пишет и читает что угодно по абсолютному пути, и вся локальная защита
edge-check упирается в потолок «двух согласованных артефактов»
(devtools#469, #478). Трипвайр #470 остаётся — он ловит запись в своё окно,
песочница её предотвращает.

## 1. Факты (замеры 2026-09-29, macOS 26.7, claude 2.1.284, codex-cli 0.156.1)

## 2. Нативная песочница харнесса или внешняя обёртка

| | Нативная (Claude Code sandbox, codex `--sandbox`) | Внешняя (`sandbox-exec` вокруг процесса) |
|---|---|---|
| Что ограничено | Claude: только Bash-команды; **файловые инструменты (Read/Write/Edit) — нет**. Codex: запись рабочим каталогом, чтение — не ограничено | весь процесс и все потомки, все инструменты |
| Где задаётся | Claude: `.claude/settings.json` в проекте — **агент может его править**; codex: флаг | профиль у раннера, вне дерева цели |
| Связка ключей | Claude: документация молчит; codex: не установлено | запрещается `mach-lookup` (F6) |
| Кода у нас | меньше | профиль + обёртка + проба |
| Риск | доверие харнессу, у каждого своя модель | F10 (DEPRECATED) |

**Решение: внешняя обёртка.** Нативная у claude не закрывает главного —
файловые инструменты и чтение токенов, а конфиг достижим агенту. Следствие
F9: у codex собственный `--sandbox workspace-write` внутри обёртки не
запустится — под обёрткой codex идёт с `--sandbox danger-full-access`,
ограничение целиком снаружи (одна модель для обоих харнессов).

## 3. Модель доступа (профиль Seatbelt)

База — `(allow default)` с запретами (как в замере), а не `(deny default)`:
пустой разрешающий список для node/codex/uv неизвестен до спайков (§7), и
`deny default` дал бы песочницу, запрещающую работу. Граница задаётся
запретами:

**Запись** — запрещена всюду, кроме:
- `target_dir` (дерево цели — туда автор пишет узел; `.git` внутри);
- у disp — каталог анкера P9 прогона (`run_dir/disp-anchors` либо
  XDG-state, `_pinned_disp_anchor_dir`);
- **свой временный каталог вызова** (`TMPDIR` = `run_dir/agent-tmp/<call>`);
  `/private/tmp` и `/private/var/folders` целиком НЕ разрешаются (F11);
- собственное состояние харнесса — перечень устанавливает спайк S1/S2
  (`~/.claude*`, `~/.codex/sessions`, кэш `uv` для disp); каждый путь — с
  обоснованием в профиле.

`run_dir/edge-check/` и остальной каталог прогона агенту **не пишутся**.

**Чтение** — запрещено: `~/.config/review`, `~/.config/gh`,
`~/.config/ai-prosto`, `~/.ssh`. **Связка ключей** — запрет `mach-lookup`
к трём сервисам (F6).

**Учётные данные модели.** Claude — из `CLAUDE_CODE_OAUTH_TOKEN` в окружении
вызова (F8; токен `claude setup-token`, хранится у оператора вне дерева
цели); codex — `~/.codex/auth.json` (чтение разрешено). **Названный
конфликт:** свой модельный токен агенту виден, а сеть открыта (нужна для
API) — агент может его вывести. Граница этого не закрывает: она про
GitHub-учётки и запись в артефакты прогона, не про модельную учётку.
Сетевой allowlist (только API модели) — вне v1, кандидат следующего среза.

## 4. Проба-канарейка (отрицательная самопроверка)

Перед КАЖДЫМ вызовом агента раннер исполняет под той же обёрткой с тем же
профилем короткий скрипт-пробу:

1. запись канарейки в `run_dir/edge-check/.sandbox-probe` и в
   `$HOME/.sandbox-probe` — обязана **не удаться**;
2. чтение файла-приманки `~/.config/ai-prosto/.sandbox-bait` (раннер кладёт
   его сам) — обязано **не удаться**;
3. `security find-generic-password -s gh:github.com` — обязано **не удаться**;
4. запись в `target_dir/.sandbox-probe` — обязана **удаться** (базовая
   половина: проба, у которой всё «не удалось», прошла бы и на профиле,
   запрещающем всё).

Любое расхождение — стоп `stopped_author` «песочница не действует: …» с
названным пунктом, **до** платного вызова; следы пробы убираются. Мутации
приёмки: убрать обёртку — проба обязана покраснеть (пункты 1–3); профиль
`deny default` без исключений — покраснеть (пункт 4).

## 5. Позитивная половина — живая приёмка

Песочница, которая запрещает всё, прошла бы пробу 1–3. Поэтому приёмка
v1 — живой прогон авторинга минимум одного узла под обёрткой на каждом
харнессе, который включается (claude; codex и disp — если включаются в v1,
§7): узел написан, гейт узла зелёный, канарейки вне списка нет.

## 6. Вне v1

- VPS / Linux (bubblewrap) — отдельным срезом, когда туда переедет авторинг (F1).
- Сетевой allowlist.
- Прочие агенты раннера: discovery (S0.5, до edge-check), ревьюер
  edge-check (без инструментов, в пустом каталоге), `ops.review` — они не в
  окне авторинга; перечень — в D12a спеки edge-check.
- Исполнители spec-runner — spec-runner#600.

## 7. Спайки до задач

- **S1 claude**: `claude -p` под профилем §3 с `CLAUDE_CODE_OAUTH_TOKEN` —
  какие пути он реально пишет (`~/.claude.json`, `~/.claude/…`), работает ли
  `--no-session-persistence` без записи в `~/.claude/projects`.
- **S2 codex**: `codex exec --sandbox danger-full-access` под профилем — пути
  записи, работа `auth.json`.
- **S3 disp**: `uv run --project disputatio disp pipeline` под профилем —
  кэш `uv`, сеть к индексу пакетов (или `--frozen --offline`), вложенные
  агенты disputatio.
- **S4**: судьба `sandbox-exec` (F10) — если Apple уберёт, запасной путь.

Решение по составу v1 (только claude или все три) — по итогам S1–S3.
