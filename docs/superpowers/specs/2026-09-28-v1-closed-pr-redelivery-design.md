# Замена отклонённой первой доставки tasks-спеки (§I10 для v1)

Дата: 2026-09-28. Статус: **draft, rev 3.1** — пара «спека + план», шлифуется
локально, доставляется одним PR. rev 3 — по второму кругу локального ревью
(5 major, 5 minor: S8 на пути возобновления, точный п.1 предиката, место
проверки переоткрытия, реализуемость Q-1(а), строгое чтение base, MERGED-v1
после замены, обёртка ошибок на месте хода, ответы повтора, перенос фактов
закрытия, `spec-loop` после замены). rev 2 — по локальному критическому ревью
rev 1 (1 blocker, 7 major): состояние «успешной доставки нет» выведено из
леджера, а не из хода (rev 1 работал на один заход); S8 evidence; гейт
«закрыл человек» вынесен владельцу (Q-1); источник фактов закрытия; гонка с
переоткрытием; проверка «спеки в base нет»; версия по §I10; гигиена тестов.
Очерёдность — решение владельца 2026-09-28: сначала devtools#445 (влит,
`a6347bd`), затем этот ход; первый живой заказчик — devtools#171.

## 1. Зачем

Владелец закрыл tasks-PR первой доставки двух воркстримов **без одобрения и не
по ошибке**: #309 и #373, 2026-09-23 — «очередь неисполненных спек растёт
быстрее, чем исполняется… понадобится эта — переиздаётся прогоном заново».
Бандлы остались одобренными, предметы — открытыми.

«Переиздаётся заново» сегодня **не исполнимо** ни одним ходом `task_bridge`
(проверено на `a6347bd`):

| Ход | На `tasks-deliver: {completed, pr: 373}` при CLOSED-unmerged #373 |
|---|---|
| обычная доставка (`--run-id`, `spec-loop`) | «уже доставлена: PR #373», RC 0 и подсказка approve для закрытого PR (`deliver_for_run`) |
| `--supersede` | `_reconcile_v1`: «PR #373 первой доставки закрыт без мержа — ветка отклонена человеком; переиздание fail-closed» |
| `--supersede --replace-revision 1` | `_validate_replacement`: «заменять можно только ревизию переиздания (N ≥ 2)» |
| `--abandon-revision 1` | v1 нет среди `tasks-deliver-v<N>` — абандонить нечего |

Докстринг `_validate_replacement` отсылает этот случай к «обычной доставке»,
но она возвращает закрытый PR. Воркстрим с отклонённой первой доставкой
отравлен навсегда. Это второй экземпляр класса (после §I10 для N ≥ 2) —
чинится механизм.

## 2. Границы

**В объёме:** состояние леджера «успешной доставки нет» и доставка из него;
явный ход, переводящий в это состояние отклонённую v1; журнал хода; гонка с
переоткрытием; правки контракта §I6/§I10 и докстрингов.

**Вне объёма:** правка леджеров #309/#373 руками; замена **открытого** PR v1
механикой (§3.1); переписывание одобрения бандла; унификация «судов по ключу
содержимого» (§7).

## 3. Состояние «успешной доставки нет» (NSD)

Ключевое решение rev 2: особый путь доставки включается **свойством
леджера**, а не конкретным ходом. Иначе он работает ровно один заход:
брошенная v2 (сдвиг base, `--abandon-revision 2`) или закрытый владельцем PR
v2 возвращают воркстрим в тупик «доставок ещё не было».

**Предикат NSD** (вычисляется в `deliver_superseded` после реконсиляции, там
же, где сегодня `prev is None` даёт отказ):

1. в леджере есть хотя бы одна запись доставки в статусе `completed`, и
   **каждая** такая запись лежит в `_replaced_revisions(state, discharged) ∪
   {skip}`; при этом `tasks-deliver` не `started` (упавшая первая доставка, у
   которой PR `spec/<ws>-tasks` мог быть создан, разбирается `deliver_for_run`,
   а не NSD — иначе рядом открылся бы `spec/<ws>-tasks-v2`). Пустой леджер —
   прежний отказ «доставок ещё не было»;
2. `_last_delivery(state, skip, discharged)` возвращает `None` (следствие
   п.1; проверяется как утверждение, не как вход);
3. **спеки `spec/<ws-id>-tasks.md` в base нет** — проверяется строгим
   примитивом `show_file_for_carry(base_sha, …)`, который различает «текст»,
   «доказанно нет» и «исключение» (`show_file` путает «нет файла» с упавшим
   `git show` и был бы открыт на ошибке). Ошибка чтения — отказ. Файл есть —
   отказ fail-closed:
   «спека в base есть, а доставки в леджере нет — леджер и base расходятся».
   Без этой проверки `supersedes: null` затёр бы доставленную спеку без
   переноса §I11.

Доставка в состоянии NSD:

| Шаг | Поведение |
|---|---|
| §I12 гейт одобрения | как всегда (§3.4) |
| S8 evidence | читается `s8-gate-verdicts.jsonl` прогона и уходит в `deliver(s8_verdicts=…)`, как у `deliver_for_run`; нет файла — отказ до эффектов. Ревизия из NSD — первая, которая дойдёт до base, и обязана нести обещанное evidence. **Признак NSD пишется в намерение** (`nsd: true`), и путь возобновления `started`-ревизии (`continue`, который сам зовёт `deliver` и до предиката не доходит) передаёт S8 тем же помощником |
| §I5 (no-op) | не применяется: доставленного содержания нет; намерение `comparison: unavailable` |
| §I8 (тот же DAG) | не производится; слово той же формы, что #443: `сверка §I8 не производилась (comparison: unavailable): предыдущей успешной доставки нет`; `dag_source: "none"` |
| §I6 (версия) | `version: 1` — см. §3.1 |
| §I11 (перенос исполнения) | переносить нечего |
| `supersedes` | `null` — утверждение, проверенное п.3 предиката |
| §I10 закрытие/чистка | существующая механика уже пропускает не-OPEN PR и `replaces_branch: null` — кода не требует |

### 3.1. Версия в NSD

В NSD доставленной спеки в base нет, и `version = 1`: контракт §I10 уже
говорит, что версия считается от base, а не от отозванного предложения, и
«может нести тот же номер». Номер отклонённого предложения повторяется
осознанно — различает два предложения ревизия и `replaces_*`, а не версия.

## 4. Ход: `--supersede --replace-revision 1 --reason "<текст>"`

Форма команды — существующий replace-переход §I10; новое — **N = 1 допустим,
если и только если PR первой доставки закрыт без мержа**. Для N ≥ 2 правила
§I10 не меняются (цепочки NSD из §3 работают для них автоматически).

### 4.1. Когда разрешён (все проверки — до единого эффекта)

1. **v1 есть и цела:** `ops["tasks-deliver"]` `completed` с целым `pr`; нет
   `pr` — `_missing_pr` (#170/#439).
2. **Состояние PR — по фордже:** `pr_facts(pr).state` = `CLOSED`. `MERGED` —
   отказ с подсказкой `--supersede`; `OPEN` — отказ с ручным выходом «закройте
   PR сами, с объяснением, и повторите» (сегодня на этом месте ошибочное «нет
   head_sha»); ошибка вызова — отказ с диагностикой, не трейсбек
   (`RealOps.pr_facts` бросает `CalledProcessError` мимо `except
   RuntimeError` в `main`). Оборачивается **на месте хода**
   (`_validate_replacement`), а не в `RealOps`: у `pr_facts` 26 вызовов в
   `governance/`, и менять их поведение этот ход не вправе.
3. **Факты закрытия — одним запросом GraphQL:** `timelineItems(itemTypes:
   [CLOSED_EVENT, REOPENED_EVENT, HEAD_REF_DELETED_EVENT], last: 3)` вместе с
   `state`/`closedAt`. Последний элемент из `ClosedEvent`/`ReopenedEvent`
   обязан быть `ClosedEvent`; записываются его `actor.login` и `createdAt`
   (`HeadRefDeletedEvent` нужен только варианту Q-1(а)). Пусто / последний — `ReopenedEvent` / запрос не удался —
   отказ fail-closed. (REST `issues/<n>/events` отвергнут: страницы по 30 от
   старых к новым и нет атомарности с `state`.)
4. **Гейт «закрыл человек»** — открытый вопрос **Q-1** (§8).
5. **Причина обязательна:** без непустого `--reason` — отказ CLI.
6. **v1 — последняя в истории:** существующая проверка «замена середины
   истории» — без изменений.

### 4.2. Что записывается

Новая ревизия `tasks-deliver-v<M>` (M = max + 1; v1 не мутируется, §I4),
write-ahead намерение:

```
replaces_revision:   1
replaces_pr:         373
replaces_branch:     null          # у v1 ветки нет
replacement_reason:  "<текст оператора>"
replaces_closed_by:  "andrei-shtanakov"          # actor последнего ClosedEvent
replaces_closed_at:  "2026-09-23T09:44:23Z"      # его createdAt
supersedes:          null          # NSD, п.3 проверен
```

### 4.3. Что переиздаётся

Ревизия генерируется **заново текущим `task_bridge` из текущего бандла на
свежем base**, не копируется из закрытого PR: сверка #171 (2026-09-28)
показала, что старая tasks-спека устарела в деталях (номера строк, фикстура v1
после #439, слово §I8 после #443). Рендер детерминирован по намерению (§I3).

### 4.4. Повтор и цепочки

- Повтор, пока новая ревизия `started`, доигрывает её (механика replace);
  следующая не заводится.
- Явный `--replace-revision 1` при уже записанной замене v1: если замена M
  **не брошена и её PR не закрыт** — объяснение «первая доставка уже заменена
  ревизией M (PR #…)», новая ревизия не заводится; если M брошена —
  продолжение по пункту ниже (перенятое обязательство); если PR M закрыт —
  отказ с подсказкой `--replace-revision M`.
- Брошенная ревизия-замена (сдвиг base / `--abandon-revision`) — следующая
  ревизия перенимает обязательство (`_pending_replacement`) и доставляется в
  NSD (§3). **Факты закрытия переносятся вместе с обязательством**: кортеж
  ключей `_pending_replacement` дополняется `replaces_closed_by`/
  `replaces_closed_at` (тест на перенос) — иначе следующая ревизия их теряет.
- PR ревизии-замены тоже закрыт владельцем — `--replace-revision M`, доставка
  снова в NSD (§3).

## 5. Гонка с переоткрытием

Переоткрытый после замены PR v1 означает две открытые PR на одну спеку;
вмерженный — разряжает отзыв задним числом (`_discharged_replacements`), и
v1 снова считается доставкой (это существующая семантика §I10 «отозванный PR
вмержен» и остаётся ею).

Правила и **место проверки** (от места зависит достижимость: цикл
реконсиляции сам отдаёт PR ревизии-замены M с кодом 0, `return_pr`):

- **`--supersede`:** проверка — **до цикла реконсиляции**, сразу после
  `_validate_replacement` (там только чтение, эффектов нет). Есть запись с
  `replaces_revision: 1`, а PR v1:
  - **OPEN** — fail-closed: «PR #… первой доставки переоткрыт после замены
    ревизией M — закройте его либо решите судьбу ревизии M явно»;
  - **MERGED**, а M **жива** (`started`, либо `completed` с открытым PR) —
    fail-closed с процедурой: в base уже лежит спека v1, а M несёт
    `supersedes: null` и `version: 1` — гарантированный конфликт add/add
    того же пути. Выход, который проверка называет: для `started` M —
    `--abandon-revision M`, затем `--supersede`; для открытого PR M —
    закрыть его, затем `--replace-revision M`. Брошенная M и M с закрытым
    PR живыми не считаются, и проверка их **не держит**: иначе названная
    процедура не снимала бы отказ, а §I10 требует отказа «ровно один раз и
    с процедурой». После разрядки отзыва (`_discharged_replacements`) v1
    снова доставка, и дальше идёт обычное переиздание;
- **`deliver_for_run`** (и `spec-loop`, который ходит через него) — внутри
  ветки `completed`, **до** раннего возврата (гейт §I12 стоит ниже и не
  мешает). При неразряженной замене v1 закрытый PR v1 **не возвращается**:
  - M `completed`, PR M открыт или вмержен — возвращается PR M со строкой
    «первая доставка заменена ревизией M» (RC 0, `spec-loop` не запирается);
  - M `started` — отказ «доиграйте `--supersede`»;
  - PR M закрыт — отказ с подсказкой `--replace-revision M`;
  - PR v1 переоткрыт — тот же fail-closed, что у `--supersede`.

## 6. Одобрение бандла

Ход переиздаёт **только tasks-спеку**. Одобрение узлов остаётся в силе, пока
байты узлов в base совпадают с одобренными, — это судит существующий гейт
§I12, общее начало всех доставок. Бандл правили после одобрения — гейт
отказывает, нужно новое одобрение; ход его не обходит.

## 7. Контракт и докстринги

- **§I10:** абзац «v1 заменяться НЕ может» → правило §4.1 (N = 1 только при
  CLOSED-unmerged; OPEN — отказ с ручным выходом); новый подраздел «Успешной
  доставки нет (NSD)» — §3 этой спеки, включая S8 и проверку спеки в base.
- **§I6:** случай «доставленной спеки в base нет» → `version = 1` (ссылка на
  §I10).
- **§I3:** без изменений — v1 в цикл реконсиляции не входит, отзыв читается
  forward-ссылкой через `_replaced_revisions`; гонка переоткрытия — §5.
- **Докстринги:** `_validate_replacement` (обещание «обычной доставки»),
  `_check_replacement_target` (сообщение для N = 1 при OPEN).
- **Не правится** (rev 1 предлагал ошибочно): `_reconcile_v1` — при
  forward-ссылке недостижим; `_replacement_close`/`_replacement_cleanup` —
  уже выходят рано на не-OPEN и `replaces_branch: null`.

## 8. Открытый вопрос владельцу

**Q-1. Гейт «закрыл человек».** Ход стоит на утверждении «первую доставку
отклонил человек». Факт форджи «CLOSED» его не доказывает: GitHub закрывает PR
сам при удалении head-ветки (во флоте есть чистильщики веток — salvage,
раннер #379), и PR мог закрыть агент (§4.1 п.2 сам отправляет оператора
закрывать). §I10 прямо признаёт: «закрыт человеком» и «закрыт нами» по фактам
форджи неразличимы.

- **(а) гейт** — отказ, если `actor` последнего `ClosedEvent` — агентская
  учётка (`review_login()` модуля `ops`, `ai-prosto`) или закрытию
  непосредственно предшествует `HeadRefDeletedEvent` того же актора (раньше
  или в ту же секунду; на #373 порядок обратный — `closed` 09:44,
  `head_ref_deleted` 10:46 — и гейт его пропускает). **Честная граница:**
  это defense-in-depth, не граница — агентская сессия, закрывающая PR через
  `gh` под профилем владельца, даёт актора-владельца; гейт ловит только
  механическое закрытие от `ai-prosto` и закрытие удалением ветки (как
  `merge-pr.sh`: правило наблюдаемо, настоящая граница — на фордже).
  **Рекомендация**: ход исполняет решение человека и не должен исполняться
  по закрытию машиной;
- **(б) журнал** — актор и время только записываются; из §4.1 убирается
  формулировка «источник закрытия проверяемый».

## 9. Отрицательные двойники (обязательные тесты)

«Нет эффекта» проверяется по `ops.calls` — ни `close_pr`, ни `ensure_branch`,
`commit_paths`, `push_branch`, `create_draft_pr` — и побайтово по `run.json`.
(`ops.touched` для этого непригоден: пишется только `last_commit_touching`.)
Двойники, которые красны и сегодня (отказ `n < 2`, отказ парсера), проверяют
**текст диагностики** нового правила, иначе они зелены до правки. Фикстура
основного сценария — **без спеки в base и в дереве** (дефолтный
`_SupersedeOps` отвечает, что спека v1 в base есть, — это не то
пост-состояние).

| Вход | Исход |
|---|---|
| **#373-подобный**: v1 закрыт владельцем ради подрезки очереди, причина задана — **основной сценарий** | ревизия доставлена в NSD: поля §4.2, `version: 1`, слово §I8, S8 в PR, v1 побайтово прежняя |
| PR v1 вмержен | отказ с подсказкой `--supersede` |
| PR v1 открыт | отказ с ручным выходом (текст) |
| `pr_facts` падает | отказ с диагностикой, не трейсбек |
| у v1 нет `pr` | `_missing_pr` |
| нет `--reason` | отказ CLI (текст нового правила) |
| последний timeline — `ReopenedEvent` / пусто | отказ fail-closed |
| Q-1(а): закрыл агент / удаление ветки | отказ (если выбран (а)) |
| спека в base есть при NSD | отказ «леджер и base расходятся» |
| нет S8 verdicts прогона | отказ до эффектов |
| повтор при `started` ревизии-замены | доигрывается, новой нет, **S8 передан в `deliver`** |
| v1 `started` + `--supersede` | прежний отказ (разбирает `deliver_for_run`), NSD не включается |
| пустой леджер + `--supersede` | прежний отказ «доставок ещё не было» |
| чтение base упало при проверке спеки | отказ, не «спеки нет» |
| M `completed` с открытым PR, v1 переоткрыт | отказ, а не `returned M` |
| v1 вмержен после замены, M жива | отказ с процедурой; **после выполнения процедуры следующий ход проходит** (обычное переиздание от v1) |
| `--replace-revision 1` при брошенной M / при закрытом PR M | продолжение / подсказка `--replace-revision M` |
| перенятое обязательство | `replaces_closed_by/at` перенесены |
| повтор при уже записанной замене v1 | объяснение, новой нет |
| ревизия-замена брошена → следующий `--supersede` | NSD-доставка с перенятым обязательством |
| PR ревизии-замены закрыт → `--replace-revision M` | NSD-доставка |
| PR v1 переоткрыт после замены | fail-closed на `--supersede` и на `deliver_for_run` |
| `deliver_for_run` после замены: M `completed` / `started` / PR M закрыт | PR M со строкой о замене / отказ «доиграйте» / подсказка `--replace-revision M`; никогда не «доставлена: PR #373» |
| бандл правлен после одобрения | отказ гейта §I12 |
| N ≥ 2 | §I10 без изменений (существующие тесты) |
