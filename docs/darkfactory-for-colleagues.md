# DarkFactory для коллег

Памятка для разработчика, который ставит DarkFactory на свой Mac и гоняет его
на своём репо. Экосистему знать не нужно.

## Что получится

Одна команда `dfl run --subject '…'` проводит цепочку:

1. агент-«заказчик» проводит с вами интервью по теме;
2. по интервью готовится бриф, `dfl run` открывает PR с брифом;
3. вы мержите бриф сами;
4. `dfl run` одобряет бриф и запускает инженерный прогон: он сам делится на
   волны и задачи и запускает `spec-runner run`;
5. на выходе проверенный PR с кодом. **Мерж кода — ваш**, агент его не мержит.

Каждый вызов `dfl run` делает ровно один шаг вперёд и печатает, что дальше.

## Что нужно

- macOS (на другой ОС `install.sh` откажет);
- `git`, `gh` (залогинен: `gh auth login`), `uv`, `claude` (залогинен);
- одна учётка GitHub: она и автор, и ревьюер, и человек (см. «Что выключено»);
- sudo не нужен.

## Установка

```sh
git clone https://github.com/andrei-shtanakov/devtools ~/darkfactory/devtools \
  && sh ~/darkfactory/devtools/install.sh
```

`install.sh` проверяет macOS, наличие `git`, `gh`, `uv`, `claude` и вход в `gh`,
затем ставит окружение devtools (`uv sync --frozen`) и запускает установщик.
Установщик клонирует рядом с devtools (в `~/darkfactory/`) закреплённые на
конкретный коммит репо из `lite/components.toml`:

- `discovery` — ставится как зависимость каталога (`uv sync`);
- `spec-runner` — ставится как утилита (`uv tool install`), даёт `spec-runner run`.

Дальше он пишет конфиг и обёртку:

- конфиг `~/.config/darkfactory/config.toml` (режим `test`, ваш логин GitHub
  на все роли). Логин берётся из `--login`, иначе из `gh api user`
  (подтверждается вопросом; `--yes` — без вопросов, если логин определился).
  Уже существующий конфиг не перезаписывается; если он не в режиме `test`,
  будет предупреждение;
- обёртка `~/.local/bin/dfl`. Если этого каталога нет в `PATH`, установщик
  напечатает строку `export PATH=…` для вашего шелла.

Опции: `sh install.sh --login <логин> --yes`.

## Подготовка репо: `dfl init-repo`

Из каталога вашего репо (он должен быть на ветке по умолчанию, дерево чистое,
`origin` на GitHub):

```sh
cd ~/code/my-repo
dfl init-repo
```

Команда открывает PR с шаблонами DarkFactory (профили, review-kit, конфиг
spec-runner), ставит на него метку `human-merge-required` и просит вас
**смержить его самому**. Свой уже открытый PR подготовки повторный вызов
находит и не дублирует; чужой PR с этой веткой — отказ.

Отказы (код 2, с причиной):

- ветка по умолчанию **требует ревью**: обязательное approving-ревью или ревью
  владельцев кода (правила ветки и rulesets). Пока агент работает под вашей же
  учёткой, GitHub не даёт одобрить собственный PR, поэтому такое правило
  заблокирует каждый мерж. `dfl` чужую защиту не меняет — снимите требование
  сами. Если правила не удалось прочитать (нет прав, ошибка `gh`), это тоже
  отказ, а не «правил нет»: проверьте `gh auth status`;
- в репо уже есть файлы назначения (конфликт) — ничего не создано, переименуйте
  или удалите их;
- остатки прерванного запуска: ветка `darkfactory/init-repo` локально или на
  origin без PR. Очистка:

  ```sh
  git branch -D darkfactory/init-repo
  git push origin --delete darkfactory/init-repo
  ```

## Запуск

```sh
cd ~/code/my-repo
dfl run --subject 'добавить экспорт отчётов в CSV'   # интервью с «заказчиком»
dfl run                                              # открывает PR брифа
# смержите PR брифа в GitHub
dfl run                                              # одобрение + инженерный прогон
dfl run                                              # (при остановке) продолжить
dfl status                                           # прогоны репо и что дальше
```

- `dfl run --stakeholder <роль>` меняет роль собеседника (по умолчанию `customer`).
- `dfl status` только читает журнал прогонов: форджу не трогает, эффектов нет.
- После перерыва (закрыли терминал, остановка по причине) просто `dfl run`.
- Когда код проверен, `dfl run` печатает: «PR с кодом проверен: <url>; мерж — за вами».
- Параллельных конвейеров в одном репо нет: пока прогон не закончен, новый
  `--subject` отказывает («конвейер репо не закончен … новая тема не
  начинается»). Закончите прогон или продолжите его `dfl run` без `--subject`.
  Если незаконченных несколько, `dfl run` просит выбрать тему.
- Нечитаемый журнал прогона блокирует `dfl run`: отказ называет каталог. Почините
  или уберите его и повторите.
- Остановка — одна строка с причиной (`stopped_…` в `dfl status`); разберите
  причину и снова `dfl run`.

`dfl` работает только в режиме `test`; при `mode = "strict"` в конфиге откажет.

## Что выключено в режиме test

Режим test **сознательно ослабляет защиты**: он для одного человека с одной
учёткой, а не для командной эксплуатации. `dfl` при каждом запуске печатает
баннер с этим перечнем. Выключено:

- репо политики утверждения не используется: утверждающий — accounts.human
- песочница авторинга: claude запускается обычным процессом пользователя (нет sandbox-exec, допуска и связки ключей)
- белый список целей: цель — из targets.toml рядом с конфигом, манифест флота необязателен
- одобрение ревью: вердикт публикуется комментарием (GitHub не даёт одобрить свой PR), вердикт обязателен
- корень доверия df (/etc/df/trust.toml) не используется: акт — по мержу (режим до миграции)

Простыми словами: учётка одна на всё; нет песочницы авторинга (она есть только
в режиме strict) — агент-автор работает с вашими правами; утверждение задач и
candidate-PR происходит автоматически; ревью приходит комментариями, а не
approve.

Репо без CI: если у PR нет проверок и в `.github/workflows` на его голове нет
файлов, после нескольких опросов с пустым списком проверок конвейер пропускает
ожидание с пометкой «проверок нет (test)». Есть workflows, но проверок пока нет —
ждёт как обычно.

## Не поддерживается в test

`criteria-close` (закрытие критериев) в режиме test не поддерживается.

## Обновление и остановки

- Обновление: `sh ~/darkfactory/devtools/install.sh` повторно (после
  `git pull` в devtools). Он переведёт компоненты на закреплённые коммиты и
  перепишет `dfl`; конфиг не тронет.
- Повторная установка **откажет посреди прогона**: «Есть незавершённые прогоны
  DarkFactory: …» (код 2) — завершите их и повторите. Также отказ при
  локальных изменениях в клоне компонента, при нештатной ветке (ожидается
  detached HEAD на закреплённом коммите) и при несовпадении `origin`.
