# Behaviour Spec: Наблюдаемость прогонов behaviour-runner

## Общие допущения

- Каждый сценарий работает с изолированным временным runtime-каталогом.
- «Построить обзор» означает получить read-model до форматирования в TTY,
  plain или JSON.
- Снимок runtime-артефактов включает содержимое и наличие файлов до и после
  действия.

#### BEH-01: Детерминированный список валидных прогонов
`traces: [FR-01, FR-02, FR-03, NFR-02]`
- **checked_by**: `status: planned` `kind: integration` `owner: qa` `target: tests/test_governance_console_model.py`

**Дано** в runtime-каталоге есть несколько валидных журналов с разными
`run_id`, `ws_id`, репозиториями, статусами, состояниями шагов и с PR либо без
него.

**Когда** консоль строит обзор два раза без изменения журналов.

**Тогда** каждый прогон присутствует ровно один раз, строки оба раза упорядочены
лексикографически по `run_id`, а поля сводки и записанные статусы совпадают с
журналами; отсутствие PR представлено как отсутствие значения, а не ошибка.

#### BEH-02: Текущий шаг нетерминального прогона
`traces: [FR-04]`
- **checked_by**: `status: planned` `kind: integration` `owner: qa` `target: tests/test_governance_console_model.py`

**Дано** валидный нетерминальный прогон, в котором часть обязательных шагов
завершена, а последующие обязательные шаги ещё не завершены.

**Когда** строится обзор.

**Тогда** поле `step` содержит первый незавершённый обязательный шаг в
каноническом порядке pipeline.

#### BEH-03: Терминальный прогон не имеет текущего шага
`traces: [FR-03, FR-04]`
- **checked_by**: `status: planned` `kind: integration` `owner: qa` `target: tests/test_governance_console_model.py`

**Дано** валидные прогоны со статусами `completed` и `merged_unverified`, у
которых могут оставаться незавершённые необязательные операции.

**Когда** строится обзор.

**Тогда** оба прогона сохраняют записанные статусы, а `step` для каждого
отсутствует.

#### BEH-04: Незнакомый строковый статус остаётся видимым
`traces: [FR-03]`
- **checked_by**: `status: planned` `kind: integration` `owner: qa` `target: tests/test_governance_console_model.py`

**Дано** валидный по форме журнал со строковым статусом, которого текущая версия
консоли не знает.

**Когда** строится обзор.

**Тогда** прогон присутствует в списке с исходным значением `status`; консоль не
подменяет его известным статусом и не классифицирует журнал как `corrupt`.

#### BEH-05: Повреждение одного журнала изолировано
`traces: [FR-05, NFR-01, NFR-04]`
- **checked_by**: `status: planned` `kind: integration` `owner: qa` `target: tests/test_governance_console_model.py`

**Дано** рядом с валидными прогонами есть каталог, где `run.json` отсутствует,
не читается, содержит невалидный JSON или имеет неверную форму.

**Когда** строится обзор.

**Тогда** для этого каталога существует ровно одна строка с именем каталога как
`run_id`, статусом `corrupt` и без домысленных предметных полей; остальные
прогоны сохранены, а произвольное содержимое повреждённого журнала не попадает в
сводку.

#### BEH-06: Пустой или отсутствующий runtime-каталог
`traces: [FR-06, FR-07, NFR-03]`
- **checked_by**: `status: planned` `kind: e2e` `owner: qa` `target: tests/test_governance_console.py`

**Дано** runtime-каталог пуст или отсутствует.

**Когда** оператор запускает plain-режим и отдельно JSON-режим в non-TTY.

**Тогда** обе команды завершаются успешно без ожидания ввода; plain stdout
равен `no runs`, а JSON stdout разбирается как пустой массив.

#### BEH-07: Явный JSON имеет приоритет над TTY
`traces: [FR-07, FR-08, NFR-03]`
- **checked_by**: `status: planned` `kind: e2e` `owner: qa` `target: tests/test_governance_console.py`

**Дано** stdin и stdout подключены к TTY и существуют валидные прогоны.

**Когда** оператор явно запрашивает JSON.

**Тогда** интерактивный интерфейс не открывается, stdout содержит только один
валидный JSON-массив, и каждый объект имеет ключи `run_id`, `ws_id`, `repo`,
`status`, `step`, `pr` и `remediated_by`, включая ключи для отсутствующих
значений.

#### BEH-08: Автоматический выбор plain и интерактивного режимов
`traces: [FR-07, NFR-03]`
- **checked_by**: `status: planned` `kind: e2e` `owner: qa` `target: tests/test_governance_console.py`

**Дано** существуют валидные прогоны и JSON явно не запрошен.

**Когда** консоль запускается сначала в non-TTY, а затем в TTY без явного
неинтерактивного режима.

**Тогда** первый запуск печатает plain-представление и не ждёт ввода, а второй
открывает работоспособный интерактивный список.

#### BEH-09: Все представления используют одну семантику
`traces: [FR-08, FR-09]`
- **checked_by**: `status: planned` `kind: integration` `owner: qa` `target: tests/test_governance_console.py`

**Дано** неизменный снимок с валидными, терминальными, нетерминальными и
повреждёнными журналами.

**Когда** из него последовательно строятся plain, JSON и TTY-представления.

**Тогда** после нормализации формата во всех трёх совпадают порядок и множество
`run_id`, а также `status` и `step` каждой строки; JSON сохраняет полный набор
стабильных ключей.

#### BEH-10: Обзор не изменяет runtime и не запускает операции
`traces: [FR-10]`
- **checked_by**: `status: planned` `kind: e2e` `owner: qa` `target: tests/test_governance_console.py`

**Дано** снимок runtime-каталога и наблюдаемый адаптер запуска pipeline-операций.

**Когда** по одному снимку строятся read-model, plain, JSON и TTY-представления
без явной команды управления.

**Тогда** снимок файлов до и после идентичен, вызовов `resume`, `verify` и иных
pipeline-операций нет, а новые runtime-артефакты не создаются.

## Покрытие смоука WS-SMOKE-001

Минимальный сквозной набор включает `running`, одно стоп-состояние,
`waiting_human_merge`, `completed`, `merged_unverified`, незнакомый строковый
статус и `corrupt`. Он выполняет BEH-01—BEH-10 на одном изолированном наборе
фикстур без ручной подмены данных между построением представлений.
