## BEH-20 / DEL-34: объём правки ограничен предметом темы

Все шесть путей лежат внутри репозитория `devtools`: ни один не начинается с
`../` и ни один не адресует файл вне рабочего дерева этого репо. Утверждения
ниже проверены прямым просмотром списка файлов и грепом дифф-а, а не
предположением о том, что тема «не могла» задеть посторонний файл.

- **Нет изменений файлов соседних репозиториев.** Список файлов дифф-а — это
  ровно шесть путей выше; каждый резолвится внутри `devtools`. Соседние
  подпроекты воркспейса (`atp-platform`, `prograph-vault`, `steward` и т.д.)
  в этом дереве вообще не примонтированы как git-объекты — `git diff` физически
  не может задеть их файлы.
- **Нет правки §I8-части контракта
  `docs/superpowers/specs/2026-09-09-tasks-supersede-contract-design.md`.**
  Проверено:

  ```
  git diff master HEAD -- docs/superpowers/specs/2026-09-09-tasks-supersede-contract-design.md
  ```

  — пустой вывод: файл не входит в список из шести затронутых путей.
- **Нет переписанных исторических ревизий леджера.** Единственный
  файл под `spec/`, тронутый этим диффом, —
  `stray-md-disables-i8-for-legacy-v1-20260922-tasks.md` (сама tasks-спека
  темы, статус чек-листа и шапка); он не леджер, а спека-документ. Файлы
  раннера состояния (`spec/.executor-*-state.db*`, `.../-task-history.log`,
  `.../-ready`) в `git ls-files spec/` для этой темы не значатся вовсе —
  это untracked runtime-артефакты исполнителя, дифф их не касается и не
  может «переписать»: git их не видит.
- **Нет ни одной временной мутации DT-03.** BEH-08/BEH-19 (TASK-002)
  вносили точечные однострочные подмены в `governance/bundle_dag.py` и

  (см. `mutation-sensitivity.md`), и откатывали их в той же сессии, до
  коммита. Проверено:


  — пустой вывод в обоих файлах на дереве `cb19d69`. Единственные
  вхождения слова «мутаци-» в этих модулях — не связанные с DT-03 фрагменты

## DEL-35: существующие ожидания наборов проходят без посторонних правок

Просмотрены дифф-и `tests/test_governance_task_bridge.py` и

<файл>`), с разделением: правки **существующих** тестов — против нового
тестового кода, добавленного этой темой (BEH-01…19, новые функции — не
«существующее ожидание», а новый сценарий, DEL-35 их не касается).

этом файле не тронута.**

### `tests/test_governance_task_bridge.py`

Дифф — 9 хунков. Восемь лежат в блоке существующих юнит-тестов
`_previous_dag` (строки ~3920–4090 в `master`); девятый — новый блок
`test_beh01_…` … `test_beh18_…` (BEH-01–18, TASK-001), целиком добавленный
код вне области DEL-35.

Из восьми хунков в блоке существующих тестов все **восемь** правят
существующие функции; правки исчерпывающе названы:

1. **Механическая распаковка третьей величины `_previous_dag`** — семь
   мест, одна и та же замена `dag, source = tb._previous_dag(...)` →
   `dag, source, _reason = tb._previous_dag(...)`, без изменения тела,
   входов или ожиданий теста:
   - `test_previous_dag_from_revision_record`
   - `test_previous_dag_derived_from_bundle_composition`
   - `test_previous_dag_legacy_requires_delivered_spec`
   - `test_previous_dag_legacy_rejects_anchor_mismatch`
   - `test_previous_dag_legacy_unparsable_frontmatter`
   - `test_previous_dag_legacy_broken_yaml_is_unavailable`
   - `test_previous_dag_legacy_rejects_malformed_traces_to`

   (Восьмое вхождение той же распаковки — в
   `test_previous_dag_unavailable_when_composition_matches_nothing`, см.
   ниже; отдельно не считается восьмым пунктом списка.)

2. **Правка, прямо относящаяся к §I8** —
   `test_previous_dag_unavailable_when_composition_matches_nothing`: помимо
   той же распаковки третьей величины, у теста заменена мутация входа —
   было `(bundle / "99-alien.md").write_text("x")` (посторонний файл), стало
   `(bundle / "15-behaviour-spec.md").unlink()` (удалён настоящий узел), и
   добавлена докстрока, объясняющая почему. Правка не косметическая: до
   исправления §I8 состав каталога сравнивался с фактическим перечнем
   `.md`-файлов без фильтрации по известным именам (**DEL-01/DEL-04**), и
   посторонний `99-alien.md` сам по себе ломал точное совпадение — это и
   был устраняемый темой дефект (**FR-01**, BEH-01/BEH-02), а не сценарий
   «состав не сошёлся ни с одним известным вариантом» (**U-1**), который
   этот тест обязан проверять. После исправления посторонний файл больше не
   двигает исход, и для того же результата (`unavailable`, U-1) тест обязан
   создавать настоящее расхождение состава — недостачу узла. Правка меняет
   тестовый вход ровно так, чтобы сценарий продолжал проверять то же
   свойство (`_previous_dag` возвращает `(None, "unavailable")` на составе,
   не совпавшем ни с одним из четырёх известных вариантов DAG), а не новое.

Больше ни одна строка существующего теста в этом файле не изменена и не
удалена — оставшийся объём дифф-а (девятый хунк) целиком новый код.
