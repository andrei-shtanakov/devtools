# DarkFactory: справка скила

Точные слова ответов, поля `dfl pending --json` и коды выхода. Источник
истины — `dfl`: на непонятный ответ `dfl reply` отказывает (код 2) с
подсказкой, вопрос остаётся ждать. Регистр слов не важен.

Язык: английские слова принимаются только там, где они названы ниже.
Enterprise-путь `dfl` ведёт всегда по-русски, `--lang` там не действует;
`неизвестно` и слова «владельца нет» — только русские, категории — русские
слова из таблицы «Починка». Поэтому в enterprise отвечай `dfl` русскими
словами (`пропустить`, `неизвестно`, `да`), человеку переводи, а дословное
поле `text` раскладки пиши словами человека как есть.

## Виды вопросов

| `kind` | Что спрашивает | Чем отвечать |
|---|---|---|
| `review` | Пауза просмотра этапа (бриф, дизайн, декомпозиция): посмотреть файлы из `links`. | `dfl reply --id <id> --text дальше` — этап готов (`дальше`, `да`, `ок`, `1`, `next`, `yes`, `ok`, `done`). Иначе — замечания словами (`--text '<замечания>'`); пустой ответ не принимается. |
| `remarks-confirm` | «Удалить D-02 …?», «Снять Must …?», «Принять правку …?»; `options` — `[<слово>, "оставить"]`. | Да: `1`, `да`, `yes` или слово вопроса (`удалить`/`remove`, `снять`/`drop`, `принять`/`accept`). Нет: `2`, `нет`, `оставить`, `оставить как было`, `keep`, `keep as it was`. |
| `edge` | Находка смысловой проверки (edge-check) и варианты решения в `options`. | Номер варианта `1`…N; `своё: <решение>` (`own: …`); `не согласен: <почему>` (`disagree: …`). После префикса нужен текст. |
| `manual` | Ручная проверка поведения (что проверить руками; `links` — где). | `1` / `выполнено` / `passed`; `2` / `не выполнено` / `failed`, можно с заметкой: `не выполнено: <что не так>`; `3` / `с оговоркой` / `принять с оговоркой` / `passed with caveat` — только с текстом: `с оговоркой: <текст>`. |
| `interview-question` | Вопрос интервью enterprise (discovery). | По существу — раскладка: `dfl answer --items <файл> --id <id>`. Не по существу: `dfl reply --id <id> --text пропустить` (`пропустить`, `не знаю`, `skip`, `don't know`). |
| `interview-topup` | Добор непокрытой обязательной темы («Не хватает: …»). | Как `interview-question`: `dfl answer --items <файл> --id <id>` или `пропустить`. |
| `interview-repair` | Починка находки проверки брифа; смысл — по `key`. | См. «Починка» ниже. |
| `interview-personal` | «Нужен бриф»: личное интервью ведёшь ты. | `dfl reply` не принимает. Реплики: `dfl note --id <id> --role agent\|human --text '…'` (у `agent` — `--option '…'` на вариант; каждая реплика `agent` — вопрос в счёт лимита, `human` — нет); бриф: `dfl brief --id <id> --file <бриф.json>` (`--accept-uncovered` — только с согласия человека). |
| `brief-confirm` | «Верно?» по сводке брифа, которую построил `dfl`. | Согласие: `1`, `да`, `верно`, `ок`, `yes`, `ok` (конечная пунктуация не важна). Любой другой ответ со словами — поправка: `поправить: <что>` / `fix: <what>` или просто текст. Голое `2` или `поправить:` без текста — отказ. |

### Починка (`interview-repair`) по `key`

| `key` | Ответ |
|---|---|
| `verdict:FR-NN` | Вердикт реализуемости: `dfl reply --id <id> --text да`, что не так — словами, или `пропустить`. |
| `category:<id>` | Категория требования словами: `скорость`, `стоимость`, `безопасность`, `регламент`, `вред людям`, `доступность`, `качество` (можно несколько). `да` — принять догадку `data.hypothesis` (предложи её как предложение). |
| `owner:<домен>` | Владелец: имя/роль словами или `неизвестно` (`никто`, `нет`, `пока нет`). |
| `assumptions` | Кто и к какой дате подтвердит допущения — словами. |
| `nfr:perf`, `nfr:cost` | Ожидания по скорости/стоимости: раскладка `dfl answer --items <файл> --id <id>` или `dfl reply --id <id> --text неизвестно`. |
| прочие (`criterion:…`, `table:…`, трассы) | Раскладка `dfl answer --items <файл> --id <id>`. |

Каждый из них можно `пропустить` через `dfl reply`. Подсказка, какой
командой отвечать, есть и в самом вопросе: `data.answer`, `accepts`.

Ответы-слова на `verdict:`, `category:`, `owner:` и `assumptions` `dfl reply`
принимает любым непустым текстом (код 0); разбирает их следующий `dfl run`.
Не разобрал (например, «категория не узнана — ответьте словами (…)») — он
отказывает с причиной, вопрос снова ждёт: переспроси человека и ответь
заново.

## `dfl pending --json`

`null` — вопроса нет. Иначе объект:

- `id` — передавать в `--id` как есть; меняется вместе с вопросом.
- `kind` — вид (таблица выше); `key` — место вопроса (у починки — что чинить).
- `text` — текст вопроса для человека; `options` — варианты (номер = позиция
  с 1); `links` — файлы/ссылки для просмотра; `accepts` — что принимается.
- `run_id`, `at` — прогон и время; `answered` — ответ уже записан
  (дальше `dfl run`).
- `data` (не у всех видов):
  - интервью enterprise: `topic`, `label` (тема), `holder`, `entries`
    (действующие пункты), `prompt` (правила и схема раскладки; вместо
    `<<ответ человека>>` подставь слова человека), `answer` (какой командой
    отвечать), у категории — `hypothesis`;
  - `interview-personal`: `subject`, `transcript` (путь к файлу журнала
    разговора `interview.jsonl` — прочитать можно, писать нельзя),
    `prompt` (путь к промпту интервьюера — прочитай файл), `lang`,
    `questions` / `max_questions`, `checks_in_row` / `max_checks_in_row`.

Файл раскладки для `dfl answer --items`: JSON
`{"text": "<слова человека>", "items": [...]}`, пункты — в схеме из
`data.prompt`. Файл брифа для `dfl brief`: объект `goals` / `functions` /
`context` / `open_items` по форме «Бриф» из промпта интервьюера, без обёртки
`{"brief": …}`.

## Коды выхода

| Команда | 0 | 1 | 2 |
|---|---|---|---|
| `dfl reply` | ответ записан — дальше `dfl run` | — | отказ: ответ не годится, вопрос другой (`id` устарел) или вопроса нет |
| `dfl answer --items` | раскладка принята и сделан следующий шаг `dfl run` (дальше — его вывод и код) | шаг `dfl run` после принятой раскладки не удался | отказ: раскладка не принята, discovery не принял, вопрос другой |
| `dfl note` | реплика записана | — | отказ: пустая реплика, `--option` у `human`, лимит вопросов, вопрос другой |
| `dfl brief` | бриф принят: сводка, ждёт `brief-confirm` | проблемы брифа перечислены — исправь и сдай снова (обычный шаг) | отказ: файл не JSON, форма не та, вопрос другой |
| `dfl run` | шаг сделан или ждёт человека («ждёт ответа») | шаг не удался — причина в выводе | отказ с причиной и «что сделать» |

Отказы печатаются блоком: команда и код, «причина», «что сделать».
Лог последнего вызова — `dfl log`; сбой, который не понять, — `dfl report`
(предложи человеку, issue уйдёт разработчикам).

## Состояние

- `dfl status` — прогоны репо и что дальше; `dfl status -v` — подробнее.
- `dfl interview --json` — что собрано в интервью (enterprise: `question`,
  `coverage`, `findings`, `readiness`; личный: `questions`, `max_questions`,
  `checks_in_row`, `draft`).
- Бросить тему — `dfl abandon` (только по просьбе человека; открытые PR он
  не закрывает).

Подробно о цикле — памятка `<devtools>/docs/darkfactory-for-colleagues.md`
(`<devtools>` — по умолчанию `~/darkfactory/devtools`, точный путь — строка
`cd "…"` в `~/.local/bin/dfl`), разделы «Без терминала (`dfl pending` /
`dfl reply`)» и «Через Claude Code Desktop».
